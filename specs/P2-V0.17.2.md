# Parallax 2.0 — Wave 4 Resumable Live Transport and Protected Reads

Status: APPROVED FOR IMPLEMENTATION
Spec ID: P2-V0.17.2
Workstream: WS-W4-LIVE-TRANSPORT / GitHub issue #146
Base: main@4097ba7ed6469f670790da92b109fbebf8280d35
Depends on: integrated P2-V0.17.1 durable run-event telemetry and deployed Wave 3 protected runtime
Method: authenticated read-only projection over authoritative Project/run, lineage and protected evidence state

## 1. Objective

Expose the durable Wave 4 run-event projection as an authenticated resumable live feed and add the bounded read-only source, diff and execution-evidence surfaces required by the Live Build experience. A browser observer may inspect authoritative facts but cannot create events, mutate source, execute commands, advance a stage, acquire a worker lease, authorize a provider, cancel work by disconnecting, or reinterpret missing telemetry as engineering success.

## 2. Scope

- Add an owner-scoped JSON event replay endpoint over the #145 durable sequence seam.
- Add an owner-scoped SSE endpoint that replays durable events after a validated cursor and then polls for newly committed events.
- Support reconnect through `Last-Event-ID` and/or a bounded `after_sequence` query cursor with one unambiguous precedence rule.
- Add exact accepted-lineage source-tree and source-file reads with strict path, size, text/binary and secret-path boundaries.
- Add exact immutable lineage-to-lineage diff reads with deterministic bounded output.
- Add bounded Engineering Attempt / protected execution evidence reads for BUILD, TEST and VERIFY without exposing arbitrary command execution or unrestricted logs.
- Add typed response schemas and narrow client API/event-stream helpers needed by later Wave 4 UI workstreams.
- Add deterministic authorization, isolation, replay, disconnect, privacy and process-recreation tests.

Event append, public unauthenticated streaming, generic repository browsing, arbitrary historical provider data, a terminal, shell execution and the Live Build UI are out of scope.

## 3. Fixed decisions

- **Read only.** Every #146 surface derives from existing authoritative Project/run, run-event, source-lineage or protected attempt evidence.
- **Owner scoped.** The authenticated principal must resolve the canonical Project/run before any cursor, lineage, path or evidence lookup is honored.
- **Durable cursor.** SSE event IDs are the positive durable #145 per-run sequence rendered as decimal text.
- **Reconnect precedence.** A syntactically valid `Last-Event-ID` header takes precedence over `after_sequence`; an invalid header fails rather than silently falling back.
- **At-least-once transport, de-duplicable identity.** Reconnect can safely replay durable sequence boundaries; clients deduplicate by exact run-event ID/sequence and never by summary text.
- **Observer independence.** Stream connect, disconnect, timeout or retry has no Engineering Run/worker mutation effect.
- **Exact lineage only.** Source and diff reads require canonical `src:<sha256>` identities already belonging to the exact Project/run.
- **No filesystem authority.** A requested path is a bounded relative POSIX identity resolved against an immutable manifest, never a server filesystem path.
- **Text source ceiling.** Source-file reads return bounded UTF-8 text only. Binary or oversized content is represented as unavailable metadata, not raw bytes/base64.
- **Bounded diffs.** Diff output is deterministic unified text generated from two exact immutable lineages under file/byte/output limits; truncation is explicit.
- **Evidence is evidence.** BUILD/TEST/VERIFY reads expose only already-bounded protected attempt fields/excerpts/digests and cannot rerun a command.
- **No provider console.** Provider credentials, headers, raw payloads, unrestricted URLs and generic provider reads remain unavailable.

## 4. Architecture requirements

### 4.1 Owner-scoped observability service

A narrow service accepts an owner-scoped Engineering Run service/repository plus #145 `RunEventRepository` and the durable lineage store. It resolves the run first and derives canonical `project_id`; caller-provided Project identity is never an authorization input.

### 4.2 Event replay endpoint

Provide an authenticated endpoint under the Engineering Run surface that returns bounded events with:

- exact `id`, `project_id`, `run_id`, positive `sequence` and deterministic `event_key`;
- typed `event_type`, `stage`, `outcome`, `subsystem`;
- safe optional attempt/worker/lineage/operation/artifact/evidence/failure references;
- bounded summary/metadata;
- `occurred_at` and durable `created_at`;
- `next_after_sequence` and `has_more` derived without inventing events.

Reads sort ascending by sequence. Limits are server bounded and invalid cursors fail closed.

### 4.3 SSE transport

Provide an authenticated SSE endpoint for one exact run. It:

- resolves the owner-scoped run before streaming;
- determines the starting cursor using the fixed reconnect rule;
- replays durable events after that cursor before waiting for new events;
- emits each event with `id: <sequence>`, a stable event name, and one JSON data object matching the bounded public event contract;
- polls the durable repository on a bounded interval rather than treating process-local memory as authority;
- emits bounded keepalive comments only when useful for connection liveness;
- stops on browser disconnect without mutating Engineering Run/worker/provider state;
- uses bounded batch size and connection duration so one observer cannot create unbounded server work.

The stream is an observation channel, not an event queue whose acknowledgement changes durable state.

### 4.4 Source tree read

For an exact lineage belonging to the owner-scoped run, return only manifest metadata already protected by source-lineage policy:

- lineage and parent identity;
- content digest, source kind, file count and total bytes;
- deterministic bounded file entries containing relative path, digest and size.

Secret-sensitive paths forbidden by the lineage contract cannot be introduced by #146. Tree pagination/limits must not permit arbitrary object-store enumeration.

### 4.5 Source file read

A source-file endpoint accepts exact lineage identity plus one relative POSIX path. The service validates the path using the same protected source policy, requires the path to exist in that lineage manifest, reads the immutable content object, verifies digest/size, and returns UTF-8 text only within a protected response ceiling.

The response includes path/digest/size/lineage identity and an explicit availability state such as `TEXT`, `BINARY`, or `TOO_LARGE`. Binary/oversized files return metadata without source bytes. No symlink, traversal, URL, absolute path or local workspace path is accepted.

### 4.6 Immutable lineage diff read

A diff endpoint requires `from_lineage` and `to_lineage`, both valid exact lineages for the same owner-scoped Project/run. It compares manifest identities first, reads content only for added/removed/changed bounded text files, and emits deterministic unified diffs with explicit file and output ceilings.

Unchanged files are summarized by count rather than copied. Binary/oversized files are reported as changed metadata without raw content. A truncated diff is explicitly marked and cannot be interpreted as a complete patch or executable mutation request.

### 4.7 Protected execution evidence read

Expose bounded read-only attempt evidence only for existing Engineering Attempts belonging to the owner-scoped run. The public shape may include stage, attempt number/status, program/model/tool identity, safe failure code, start/completion timestamps and a strict allowlist of protected execution evidence already persisted by Wave 3.

For BUILD/TEST/VERIFY, allowed evidence includes exact source-lineage/command identity, exit code, timeout/redaction/network policy, bounded stdout/stderr excerpts or digests already accepted by the protected execution contract, duration and acceptance coverage. Arbitrary keys, raw environment, headers, cookies, credentials, prompts/reasoning, provider payloads and unbounded logs are excluded even if malformed legacy evidence contains them.

### 4.8 Client transport helper

A narrow web client helper may:

- fetch paged event replay;
- open an authenticated same-origin SSE stream;
- retain the last accepted positive sequence per run in in-memory/client state;
- ignore an event whose sequence is not greater than the last rendered sequence;
- expose transport states such as CONNECTING / LIVE / RECONNECTING / CLOSED / ERROR independently from Engineering Run state.

It cannot append events or infer run cancellation/failure from transport closure.

## 5. Security and privacy

- All endpoints use the existing protected authentication boundary; `/health` and `/ready` remain the only intentionally public operational probes.
- Owner-scoped run resolution occurs before revealing whether a lineage, path, event, attempt or evidence reference exists.
- Cross-Project/run event, lineage or attempt association returns the same protected not-found/denial posture as existing owner-scoped APIs.
- Cursor values are nonnegative bounded integers only; malformed or excessively large values fail validation.
- Source paths use the existing lineage path policy, including `.env*`, `.git`, `.ssh`, credential filenames and key/certificate exclusions.
- Source content is never returned for a path not present in the exact immutable manifest.
- Binary content is not base64-encoded into the API merely to bypass the text boundary.
- Evidence serialization uses an explicit allowlist and re-applies bounded secret-sensitive field/value checks before response.
- SSE data contains only the same bounded public event schema available through authenticated JSON replay.
- Keepalives contain no Project/run/source/provider content.
- No endpoint accepts generic URL, shell, command, environment, header, cookie, provider token, repository credential or filesystem-root parameters.
- Browser disconnect never calls pause, cancel, worker stall, retry, provider mutation or stage transition code.

## 6. Failure and recovery boundaries

- Reconnect after process recreation reads from durable #145 events and continues after the requested durable sequence.
- Duplicate delivery caused by reconnect is safe because event ID and sequence are stable; the client helper suppresses already-rendered sequences.
- A cursor greater than the current durable maximum returns/waits for future events without fabricating gaps or synthetic success.
- Invalid `Last-Event-ID` fails the stream request; it is never ignored in favor of a weaker query cursor.
- Event repository failure terminates/fails the observation request and does not alter the Engineering Run.
- Lineage/object integrity failure returns an explicit protected read failure; source bytes are not returned from partially verified state.
- A diff bound being reached sets `truncated=true`; no silent clipping is permitted.
- Malformed legacy attempt evidence is filtered or rejected as unavailable rather than serialized wholesale.
- SSE disconnect and server connection timeout are transport facts only and do not create run events by themselves.

## 7. Non-goals

- changing #145 append/event identity semantics;
- replacing Engineering Run, attempt, worker, lineage, provider or evaluation authority;
- adding WebSocket command/control or bidirectional agent transport;
- exposing a generic terminal, shell, process manager, filesystem browser or object-store browser;
- arbitrary GitHub/Vercel/provider API reads;
- editing, applying or publishing a diff from the read endpoint;
- exposing binary source blobs, secrets, environment variables, credentials, prompts, scratchpads or hidden reasoning;
- implementing the final Live Build visual shell;
- applying the #145 production migration or deploying from this worker branch.

## 8. Acceptance criteria

### AC-01 Owner-scoped event replay is deterministic and bounded
Authenticated JSON replay resolves the canonical owner-scoped run first and returns ascending durable #145 events after a nonnegative cursor with bounded limits and stable public identities.

### AC-02 SSE replays and resumes from durable sequence
The authenticated SSE route replays persisted events after its resolved cursor, emits durable sequence IDs, observes newly committed events through bounded polling and survives process recreation without process-local event authority.

### AC-03 Reconnect cursor semantics are unambiguous and duplicate-safe
Valid `Last-Event-ID` takes precedence over the query cursor, invalid headers fail closed, and permanent tests prove reconnect/replay cannot cause duplicate rendered event identity when the client helper tracks the last accepted sequence.

### AC-04 Observer connection state cannot mutate engineering state
Connect, keepalive, disconnect, reconnect, timeout and stream failure never pause/cancel/advance a run, acquire/reassign a worker, mutate source, publish a provider action or fabricate run-event success.

### AC-05 Exact-lineage source tree reads preserve Project/run and secret-path isolation
Tree reads require an exact lineage belonging to the owner-scoped Project/run and expose only bounded immutable manifest metadata protected by the existing lineage source-path policy.

### AC-06 Exact-lineage file reads return only verified bounded UTF-8 source
A requested relative path must be policy-valid and present in the exact lineage. Returned text must match immutable object digest/size and response bounds; binary/oversized/secret/traversal inputs never return raw content.

### AC-07 Immutable diffs are deterministic, bounded and non-authoritative
Diffs require two exact same-run lineages, report deterministic added/removed/changed results, explicitly mark binary/oversized/truncated cases and cannot be applied as a mutation request.

### AC-08 Protected attempt/evidence reads cannot become a terminal or log dump
Read-only attempt evidence is owner scoped and allowlisted. BUILD/TEST/VERIFY may expose bounded already-persisted execution excerpts/digests and identities, while arbitrary commands, raw environment, credentials, provider payloads, prompts/reasoning and unbounded logs remain absent.

### AC-09 Cross-Project/run and reference probing fail closed
Tests prove another owner, wrong Project/run, foreign lineage, foreign attempt, invalid path and malformed cursor cannot reveal protected existence or content.

### AC-10 Transport and protected-read failures remain truthful
Repository/object/evidence failures, cursor errors and diff truncation remain explicit observation failures/states and cannot change authoritative runtime outcomes or be represented as engineering success.

### AC-11 Permanent tests cover replay, process recreation, disconnect, privacy and bounds
Deterministic tests cover JSON paging, SSE replay/live polling/reconnect, client deduplication, process-recreated repository reads, disconnect independence, source/file/diff bounds, secret-path denial, binary behavior, evidence allowlisting and cross-scope isolation.

### AC-12 Existing protected runtime and exact-head gates remain green
The final candidate has authentic committed DSPy plan evidence and passes Workstream Spec Validation, Parallax P2 CI and Bounded Autonomy on the exact final head with existing Wave 3/#145 protected suites unchanged or stronger. The worker stops review-ready before merge, migration application or deployment.

## 9. Release gate

Before #146 is READY FOR INTEGRATION, AC-01 through AC-12 must be implemented and deterministically tested; the transport must remain authenticated, read-only, resumable and non-authoritative; source/diff/evidence reads must preserve exact immutable identity and privacy bounds; authentic DSPy SpecCritic/SpecCompiler evidence must be committed; the branch must be current with its accepted base and pass Workstream Spec Validation, P2 CI and Bounded Autonomy on the exact final head. No production migration or deployment occurs from this worker workstream.
