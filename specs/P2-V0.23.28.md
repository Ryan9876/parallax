## 1. Objective

Remove the later bounded post-generation/pre-BUILD blocker exposed by the authenticated P2-V0.23.27 retry of Engineering Run `3a1ba66a-5649-42b6-81ee-91684fe06bbc`.

The exact production P2-V0.23.27 deployment remained healthy. The authenticated run reached durable sequence #86: PLAN completed at evidence #79, worker checkpoint #85 persisted CHECKPOINTED state at 1:58:54 PM, and IMPLEMENT attempt 6 failed at evidence #86 at 1:58:55 PM with `AUTONOMOUS_IMPLEMENT_FAILED`. Source-lineage reads succeeded. Luna and Terra each completed real hosted generation immediately before the failure. No Sol/final validator-repair generation and no disposable candidate BUILD/TEST/VERIFY sandbox followed Terra.

P2-V0.23.27 moved safe-preflight convergence inside each work unit, but plan-level combination is still checked only after work units are completed. A work-unit proposal can therefore pass its own combined safe preflight and still conflict with the already completed plan prefix or an aggregate whole-plan safe-engine rule. That rejection currently occurs after the work-unit recovery loop has ended, so there is no bounded semantic repair opportunity.

P2-V0.23.27 also introduced bounded `candidate_generation_failure` evidence, but `implementation_runtime._bounded_implementation_failure_evidence()` currently admits only `candidate_admission_failure` and `candidate_validation_failure`. The new convergence diagnostics are therefore dropped before durable failed IMPLEMENT evidence is persisted.

P2-V0.23.28 makes convergence plan-prefix-aware while preserving every existing safety and authority boundary. Before a work unit is completed, its converged proposal is checked together with already completed work-unit patches using the unchanged `SafeImplementationEngine` preflight. A plan-prefix rejection keeps the current work unit inside the existing finite candidate-recovery loop and supplies only a fixed sanitized reason code. The final whole-plan preflight remains defense in depth. The runtime also preserves a strictly bounded sanitized `candidate_generation_failure` diagnostic envelope through durable failed IMPLEMENT evidence.

## 5. Architecture requirements

### 5.1 Plan-prefix-aware safe preflight

The resilient live candidate-recovery controller already maintains the ordered patches emitted by completed work units. After the current work unit reaches P2-V0.23.27 local convergence but before assignment admission is finalized into `completed`, the controller must construct a temporary canonical proposal containing:

- all already completed plan-prefix patches; and
- the current work unit's locally converged patches.

The proposal is checked using the same `ProposalSafetyPreflight` callable supplied by `ProtectedImplementationRuntime`.

This check is read-only and grants no source, lineage, lifecycle, deployment, or REVIEW authority.

### 5.2 Current-unit recovery on plan-prefix rejection

If the plan-prefix proposal fails safe preflight:

- the current work unit is not marked complete;
- its patches are not appended to the completed plan-prefix patch list;
- the sanitized reason code from `ProposalSafetyPreflight.reason()` becomes bounded convergence rejection evidence;
- already completed work-unit patches remain unchanged;
- the current work unit advances through the existing distinct-agent recovery sequence;
- if distinct agents are exhausted, the existing one final validator repair is the only additional semantic repair opportunity;
- no retry or timeout budget is increased.

The repair request may contain only the fixed rejection reason code plus the already permitted bounded retained/rejected target names. It may not contain prior patch contents, generated content, diffs, source digests, exception text, provider payloads, credentials, or filesystem roots.

### 5.3 Local accumulator rollback semantics

A plan-prefix rejection must not permanently poison the current work-unit accumulator with the rejected generation's newly accepted patch set. Previously retained patches from earlier incomplete generations of that same work unit may remain only if they were retained before the rejected current generation and remain independently safe.

The implementation may satisfy this by previewing convergence before committing new retained patches, by adding an explicit rollback-capable evaluation boundary, or by an equivalent deterministic mechanism. It must not mutate canonical source.

### 5.4 Final whole-plan preflight remains authoritative

After all work units are complete, the controller still constructs the exact final `ImplementationProposal`, validates exact protected acceptance coverage, and calls the unchanged whole-plan safe preflight before candidate BUILD/TEST/VERIFY.

This check is defense in depth. A failure remains fail-closed and must carry a bounded sanitized diagnostic rather than arbitrary exception text. No implementation may remove the final check merely because plan-prefix checks were introduced.

### 5.5 Durable candidate-generation failure diagnostics

`ImplementationRuntimeError` may preserve a `candidate_generation_failure` envelope only when it conforms to a strict server-owned schema.

Allowed top-level generation fields are limited to:
- `reason_code` equal to `CANDIDATE_GENERATION_EXHAUSTED`;
- non-negative bounded integer counts such as rejection count, retained patch count, rejected patch count, validator repair count/limit, and existing reassignment ceiling;
- a bounded list of fixed preflight/recovery reason codes;
- a bounded list of candidate rejection records already normalized by the server;
- explicit false authority flags including `canonical_source_mutated`, `source_lineage_accepted`, and `worker_process_loss`.

Allowed nested candidate-rejection fields are limited to server-owned work-unit identity, agent identity digest, generation, fixed failure kind, validator-repair boolean, retained/rejected counts, fixed rejection reason codes, progress boolean, and explicit false authority flags.

All strings must satisfy existing bounded identity/digest/reason vocabularies. Unknown fields or non-false authority claims cause the diagnostic envelope to be dropped rather than weakening fail-closed behavior.

## 6. Security

Plan-prefix convergence does not widen model, source, mutation, lineage, lifecycle, Git, deployment, or REVIEW authority. Every prefix and final proposal remains checked by the existing server-owned `SafeImplementationEngine` preflight. Retained and current intent remains non-authoritative until disposable BUILD/TEST/VERIFY, independent evaluation, final commit-time validation, and source-lineage acceptance succeed through their existing protected boundaries.

A plan-prefix rejection may feed back only fixed server-owned sanitized reason codes and already-bounded repository-relative target names. Raw source, generated content, unified diffs, source digests, exception text, provider payloads, credentials, tokens, environment values, and filesystem roots are prohibited from repair guidance and durable failure evidence.

Candidate-generation failure diagnostics are observation only. The sanitizer uses a closed schema and fixed vocabularies, rejects unknown fields or true authority claims, and drops invalid diagnostics rather than weakening or blocking the authoritative IMPLEMENT failure transition. Existing path, secret, symlink, stale-base, collision, hierarchy, size, model, retry, timeout, Git/deployment/lifecycle, and human REVIEW controls remain unchanged.

## 7. Reliability

Moving the existing whole-proposal safety check earlier reduces avoidable terminal failures without weakening fail-closed behavior. If plan-prefix convergence cannot produce a safe proposal inside the unchanged finite recovery budget, IMPLEMENT remains failed with no canonical source mutation. Previously completed work-unit intent remains deterministic and non-authoritative, and current-generation additions are not retained when the plan-prefix check rejects them.

The final whole-plan safe preflight remains mandatory defense in depth even when all prefix checks pass. Diagnostic sanitization failure never converts failure into success and never creates a second source of lifecycle authority.
