## 1. Objective

Correct one classification boundary exposed by the authenticated frozen W9-S1 Decision Ledger replay after P2-V0.23.35. The exact production deployment now restores scoped Vercel Connect credentials, but source bootstrap for the fresh approved target `Ryan9876/parallax-qa1` stops at `provider-repository` with `PROVIDER_INVALID_RESPONSE` before the existing greenfield fallback can perform its protected authenticated empty-repository inspection.

Parallax already has an accepted greenfield contract from P2-V0.23.7 / Architecture v3.21: public source failure is not sufficient to classify a repository as empty; exact authenticated repository inspection must positively prove the target is empty before a zero-file durable greenfield root may be created. P2-V0.23.36 must preserve that authority model and only distinguish a valid Git smart-HTTP advertisement with no commit-bearing HEAD from malformed provider data.

## 2. Root cause

`PublicGitHubArchiveReadClient._advertised_head()` currently requires both a commit SHA for `HEAD` and a `symref=HEAD:<branch>` capability. A valid truly empty GitHub repository has no commit-bearing advertised HEAD. The current implementation therefore raises `PROVIDER_INVALID_RESPONSE`.

`GreenfieldProjectedRepositoryLineageBootstrap.ensure()` is designed to catch ordinary source-bootstrap failure and then invoke `GreenfieldGitHubActions.inspect_repository()` through the exact authenticated repository capability. That protected inspection can prove `is_empty=true` and create the existing zero-file durable root. Because the public reader labels the valid empty advertisement as malformed provider data, the observed runtime evidence is misleading and the source path stops before the intended greenfield decision boundary.

## 3. Required behavior

### 3.1 Valid empty public advertisement

When GitHub returns a syntactically valid Git upload-pack advertisement that contains no commit-bearing refs, the public archive reader must classify the result as `SOURCE_NOT_FOUND`, meaning no commit-bearing public source exists.

This classification is source absence only. It MUST NOT mean the repository is trusted as empty and MUST NOT directly create greenfield lineage.

### 3.2 Protected empty determination

After public source absence, the existing `GreenfieldProjectedRepositoryLineageBootstrap` fallback must continue to perform exact authenticated repository inspection. Only a positive protected inspection with `is_empty=true` may authorize the existing zero-file durable `greenfield` root.

If inspection reports non-empty, authorization required, provider failure, mismatch, or ambiguous evidence, the run remains fail-closed under existing behavior.

### 3.3 Malformed advertisement

Malformed packet framing, invalid packet lengths, non-ASCII protocol material where ASCII is required, malformed ref records, or protocol material that claims refs but cannot establish a valid commit-bearing HEAD/default-branch contract must continue to fail as `PROVIDER_INVALID_RESPONSE` or the existing protected provider error. P2-V0.23.36 must not convert arbitrary parse failures into greenfield eligibility.

### 3.4 No mutation or authority expansion

No repository initialization, branch creation, commit, pull request, Preview creation, or REVIEW transition may occur during source bootstrap. Empty repository initialization remains REVIEW-only under the existing `repository.initialize-empty` capability.

No model/provider/tool capability, repository scope, credential permission, source-lineage authority, retry/timeout, deployment authority, lifecycle authority, or REVIEW authority is added.

## 4. Implementation boundary

Expected semantic change:

- `services/api/parallax_api/code/public_github_archive.py`
  - distinguish a syntactically valid no-ref upload-pack advertisement from malformed protocol data;
  - return/raise the existing `SOURCE_NOT_FOUND` source-absence code for the valid no-ref condition;
  - retain existing invalid-response behavior for malformed/ambiguous advertisements.

Expected tests:

- focused public archive unit regression for a valid empty upload-pack advertisement;
- malformed-advertisement regression proving fail-closed behavior remains unchanged;
- greenfield bootstrap/composition regression proving public source absence still requires protected authenticated empty inspection before zero-file lineage initialization.

No other runtime path should change unless required to make the protected distinction explicit and testable.

## 5. Security and trust invariants

1. Public Git protocol evidence is source evidence, never empty-repository authority.
2. Exact authenticated repository inspection remains the only runtime authority that may prove a target is empty.
3. A valid no-ref public advertisement may only mean `SOURCE_NOT_FOUND`.
4. Malformed/ambiguous provider payloads remain fail closed.
5. Caller/model/benchmark input cannot select provider credentials, repository scope, source revision, greenfield status, initializer capability, branch, commit, Preview, or REVIEW outcome.
6. Exact repository scope and least-privilege Connect credentials from P2-V0.23.35 remain unchanged.
7. Source mutation remains prohibited before verified REVIEW delivery.

## 6. Acceptance criteria

### AC-01 — Valid empty advertisement is source absence
A syntactically valid Git upload-pack advertisement with no commit-bearing refs does not raise `PROVIDER_INVALID_RESPONSE`; the public source path produces normalized `SOURCE_NOT_FOUND`.

### AC-02 — Malformed advertisement remains invalid
Malformed packet framing or invalid protocol payload continues to raise `PROVIDER_INVALID_RESPONSE` and cannot enter greenfield classification.

### AC-03 — Positive protected inspection remains mandatory
A source-absent public path does not create greenfield lineage by itself. The greenfield wrapper invokes authenticated exact-repository inspection and only `is_empty=true` may initialize the zero-file durable root.

### AC-04 — Non-empty/ambiguous protected inspection fails closed
If authenticated inspection is non-empty or fails without the explicit repository-authorization condition, the original source bootstrap failure remains authoritative and no mutation occurs.

### AC-05 — Existing authorization behavior preserved
`REPOSITORY_AUTHORIZATION_REQUIRED` remains the explicit same-run human/provider authorization boundary when exact repository inspection proves the credential does not cover the target.

### AC-06 — Regression safety
Focused tests, full applicable API suite, compile checks, exact DSPy spec validation, protected promotion/regression checks, and bounded autonomy gates pass on the exact release head.

### AC-07 — Production deployment verification
The exact merged application source deploys READY to `parallax-api`, production `/health` returns HTTP 200, `/ready` returns HTTP 200 with database/providers ready, and the exact-deployment runtime error scan is reviewed.

### AC-08 — W9-S1 advances beyond current blocker
