# P2-V0.13.7 — In-flow Composer Clearance

Status: IMPLEMENTATION CANDIDATE
Date: 2026-08-22

## Objective

Guarantee that the persistent composer never covers conversation content on supported mobile or desktop viewports, including when a Work Specification is expanded, an amendment hand-off is visible, or the iOS software keyboard has just closed.

## Problem

The production composer is absolutely positioned over the conversation thread. Bottom padding is estimated from the measured composer height, which can still leave newly loaded or amendment-state content visually underneath the composer. The 2026-08-22 iPhone production screenshot shows the newest assistant response beginning behind the composer even with the keyboard closed.

## Requirements

1. The composer must reserve real layout space instead of overlaying the conversation thread.
2. The conversation thread must remain the flexible scroll region between governed surfaces and the composer.
3. The thread must be allowed to shrink to zero/minimum height when the Work Specification consumes substantial vertical space.
4. At the bottom scroll position, the newest response and amendment notice must remain fully reachable above the composer.
5. The v0.13.6 visual-viewport keyboard behavior must remain intact.
6. Mobile interaction targets, Work Specification authority, amendment semantics, Engineering Run authority, authentication, and bounded-autonomy behavior are unchanged.
7. Reduced-graphics mode must preserve the same composer-clearance behavior.

## Acceptance criteria

- A 390×844 browser regression fixture with an expanded draft specification, user turn, assistant response, and amendment notice can scroll to the live edge without the response/notice intersecting the composer.
- The composer remains visible and in-flow with the keyboard-closed viewport.
- The existing 390×844 expanded Work Specification geometry test continues to pass.
- The existing iOS keyboard-visible visual-viewport regression test continues to pass.
- Client typecheck, web export, browser/Skia acceptance, API regression, protected promotion evaluation, DSPy release compilation, and bounded-autonomy gates remain green.

## Non-goals

- Changing the composer visual language.
- Changing Work Specification generation or approval behavior.
- Changing response content or amendment classification.
- Expanding autonomous source-editing or deployment authority.
