## 1. Objective

Remove the next real production IMPLEMENT bottleneck exposed by authenticated Engineering Run `3a1ba66a-5649-42b6-81ee-91684fe06bbc` on P2-V0.23.26.

P2-V0.23.26 successfully removed model-owned unified-diff mechanics. On the authenticated production retry, Luna and Terra returned server-canonicalized proposals that reached the safe proposal validator but were rejected, Sol hit the unchanged bounded 60-second timeout, and the final fresh Terra validator-repair generation was also rejected. No canonical source mutation occurred, source-lineage reads succeeded, and the API remained healthy.

The remaining failure is admission granularity. A proposal may contain useful independent file edits plus one unsafe or stale edit, but the current model router receives only a whole-proposal boolean. One rejected patch therefore discards every valid patch and forces the next admitted model to regenerate the whole work unit. The repair loop also sees only generic `VALIDATION_EXHAUSTED`, so it cannot target the server-owned rejection class.

P2-V0.23.27 changes the resilient live IMPLEMENT candidate-recovery boundary from all-or-nothing proposal admission to bounded incremental convergence. Independently safe canonical patches may be retained as non-authoritative candidate intent across the existing finite model generations. Rejected patches are isolated with sanitized reason codes. A work unit is complete only when the combined retained proposal passes the unchanged whole-proposal `SafeImplementationEngine` preflight. Final mutation, source-lineage acceptance, BUILD/TEST/VERIFY, delivery, Git/deployment and human REVIEW authority remain unchanged.

## 2. Fixed decisions

- The approved Work Specification and exact acceptance IDs remain authoritative.
- `ImplementationContentProposal`, server-canonicalized `ImplementationProposal`, `GeneratedSourcePatch`, `SourcePatch`, `CanonicalizingTextPatchEngine` and `SafeImplementationEngine` remain the canonical generation and mutation contracts.
- The protected runtime adds a sanitized server-owned preflight classifier that maps safe-engine exceptions to a fixed bounded reason-code vocabulary without returning exception text, source text, generated content, filesystem roots, provider payloads or secret material.
- The resilient live candidate-recovery path may validate each canonical patch independently against the authoritative workspace before whole-proposal admission.
- Independently safe, non-overlapping patches may be retained across existing bounded model generations within the same work unit. Retention is candidate evidence only: it grants no source mutation, lineage, BUILD, deployment, lifecycle or REVIEW authority.
- Subsequent repair generations receive only the exact acceptance contract, existing protected source context, retained target names, and sanitized rejection reason codes. Retained patch contents and rejected raw outputs are never copied into repair guidance.
- A model generation that repeats a retained target does not overwrite retained intent. Repetition is a bounded rejection signal.
- Target ancestor/descendant conflicts are rejected deterministically before retention. The runtime never tries to resolve conflicting path ownership by mutation or arbitrary model preference.
- A work unit converges only when the combined retained plus newly accepted patches pass the unchanged whole-proposal safe preflight. Individual-patch acceptance alone is insufficient.
- If combined preflight rejects the new combined set, only patches newly introduced by that generation are discarded; previously retained independently safe patches remain non-authoritative retained intent for the next bounded generation.
- A generation that yields no independently safe new patch is a no-progress rejection and consumes the existing candidate-recovery path exactly as today.
- The distinct-agent reassignment ceiling, one final validator repair per work unit, admitted Luna/Terra/Sol roster, 60-second hosted timeout, zero hidden provider retries and request-level autonomy budget are unchanged.
- Final candidate BUILD/TEST/VERIFY remains mandatory after proposal convergence. Incremental preflight does not claim functional correctness.
- Architecture advances to v3.38 because the durable proposal-admission and repair contract changes from whole-candidate regeneration to retained bounded per-file convergence.

## 5. Architecture requirements

### 5.1 Sanitized preflight classification

The protected implementation runtime must expose a server-owned classifier for a canonical proposal. It returns `None` only when `SafeImplementationEngine.validate()` succeeds. Failures are mapped by exception type to a fixed bounded reason code.

The allowed reason-code vocabulary must include at least:
- `UNSAFE_TARGET` for unsafe path, unsupported target, symlink, secret-sensitive target/content or containment rejection represented by `UnsafeTargetError`;
- `STALE_BASE` for authoritative-base or existing/unselected collision mismatch represented by `StaleBaseError`;
- `PATCH_FORMAT` for strict/canonical patch representation rejection represented by `PatchFormatError`;
- `PATCH_CONFLICT` for no-op or non-applying content represented by `PatchConflictError`;
- `PATCH_LIMIT` for per-patch source/patch/result/missing-parent bounds represented by `PatchLimitError`;
- `DUPLICATE_TARGET` and `TARGET_HIERARCHY_CONFLICT` for whole-request conflicts;
- `IMPLEMENTATION_LIMIT` for aggregate safe-engine bounds;
- `SAFE_IMPLEMENTATION_ERROR`, `OS_BOUNDARY_ERROR` and `UNKNOWN_PRECHECK_ERROR` as bounded fallbacks.

Exception messages are not surfaced through this classifier. The classifier must not mutate source.

### 5.2 Independent patch preflight

For a generated work-unit proposal, the resilient candidate-recovery runtime must construct one-patch canonical proposals using the exact work-unit acceptance IDs and call the server-owned preflight classifier.

A patch whose classifier result is `None` is independently safe candidate intent. A rejected patch is not admitted or persisted as source and contributes only its target path plus bounded reason code to repair state.

The original full generated proposal is not automatically authoritative because one or more component patches are independently safe.

### 5.3 Retained patch convergence

Within one work unit and only inside the existing bounded candidate generation loop, the runtime maintains a deterministic map of retained independently safe patches keyed by normalized canonical target path.

New safe patches are eligible for retention only when:
- the target is not already retained;
- the target does not have an ancestor/descendant conflict with another retained or same-generation safe target; and
- the patch independently passes the protected classifier.

Retained intent is immutable for the remainder of that work-unit convergence attempt. A later model cannot overwrite a retained target. Repeated retained targets become `RETAINED_TARGET_REPEATED` rejection evidence.

### 5.4 Combined preflight remains authoritative

After each generation produces at least one new independently safe patch, the runtime combines prior retained patches with the generation's eligible new safe patches and constructs the existing `ImplementationProposal` for the work-unit acceptance IDs.

Only if the unchanged whole-proposal safe validator succeeds is that work unit complete.

If combined preflight fails:
- the runtime obtains the sanitized whole-proposal reason code;
- patches introduced by the current generation are not retained;
- prior retained patches remain unchanged candidate intent;
- the generation is treated as incomplete and consumes the existing bounded recovery sequence.

This prevents an aggregate limit or cross-patch conflict from poisoning previously isolated safe intent while retaining the unchanged final safe-engine authority.

### 5.5 Bounded targeted repair guidance

A subsequent candidate generation may receive a server-owned constraint summarizing convergence state. The constraint may contain only:
- sorted retained repository-relative target paths;
- sorted rejected repository-relative target paths;
- fixed sanitized rejection reason codes;
- the instruction not to repeat retained targets;
- the instruction to return only semantic `{path, content}` intent and let the server own patch mechanics.

The constraint may not contain retained/rejected file contents, unified diffs, source digests, exception text, filesystem roots, provider payloads, credentials or environment values.

Target/reason evidence is bounded by the existing maximum proposal patch count and path length. No new generation is added solely for diagnostics.

### 5.6 Existing recovery budgets remain finite

A partial generation that does not produce a combined-safe proposal counts as an incomplete/rejected candidate generation and advances through the same deterministic distinct-agent recovery sequence.

If distinct admitted agents are exhausted, the existing single final validator repair remains the only additional semantic repair opportunity. The final repair receives the same bounded convergence summary plus the existing cache-distinct final context token.

No retry ceiling or timeout is increased.

### 5.7 Durable evidence remains non-authoritative and bounded

Candidate rejection/convergence evidence may include:
- work-unit ID;
- generation number;
- sanitized failure kind;
- retained patch count;
- rejected patch count;
- reason-code counts;
- whether any current-generation progress was made;
- `canonical_source_mutated=false`;
- `source_lineage_accepted=false`;
- `git_mutation=false`;
- `deployment_mutation=false`;
- `review_completed=false`.

Raw source, patch text, generated content and exception text remain excluded.

A durable selected candidate artifact is persisted only after the existing candidate selection and protected BUILD/TEST/VERIFY path establishes the normal selected candidate. Retained partial intent is not a canonical lineage artifact.

### 5.8 Final mutation boundary is unchanged

After convergence and protected candidate validation, `ProtectedImplementationRuntime` still:
- verifies exact acceptance coverage;
- rebuilds the existing `ImplementationRequest`;
- calls the same `SafeImplementationEngine.apply()` on the exact authoritative workspace;
- accepts source lineage only through the existing lineage gateway;
- completes IMPLEMENT only through `EngineeringRunService`.

No incremental convergence operation mutates canonical source.

## 6. Security and reliability

Incremental convergence does not trust model output more; it reduces unnecessary regeneration while preserving every authoritative check. Each retained patch has already passed the existing safe engine independently, but it remains non-authoritative until the complete proposal passes combined preflight, disposable candidate BUILD/TEST/VERIFY, final commit-time revalidation and source-lineage acceptance.

Sanitized reason codes are server-derived from exception classes. They improve repair quality without exposing protected exception text or source. Target paths may be fed back only because they originated as bounded repository-relative candidate targets and remain subject to the existing target-length/proposal-count bounds.

A safe individual patch can still conflict with another safe individual patch. The combined safe preflight therefore remains mandatory. The convergence layer must never infer that individual acceptance implies combined safety or functional correctness.

Failure remains fail-closed. Exhausting the unchanged bounded candidate/repair budget leaves IMPLEMENT failed with no canonical mutation.

## 7. Acceptance criteria

### AC-01 Safe preflight classifier is truthful and sanitized
Representative `UnsafeTargetError`, `StaleBaseError`, `PatchFormatError`, `PatchConflictError`, `PatchLimitError`, duplicate, hierarchy and aggregate implementation failures map to fixed reason codes. No test-visible classifier output contains arbitrary exception text or source content.

### AC-02 Independently safe patches are retained
Given a generated proposal containing one safe canonical patch and one rejected patch, the resilient work-unit loop retains the safe patch as non-authoritative intent instead of discarding it when moving to the next admitted generation.

### AC-03 Rejected patches are isolated
Rejected patches never enter the retained patch map, final combined proposal, candidate artifact or canonical workspace unless a later generation returns a separately safe replacement.

### AC-04 Repair generation receives bounded convergence context
After partial progress, the next admitted generation receives retained target names and sanitized rejection codes, does not receive retained/rejected content or unified diffs, and is instructed not to repeat retained targets.

### AC-05 Repeated retained targets do not overwrite intent
If a later generation returns a path already retained, that patch is rejected as `RETAINED_TARGET_REPEATED`; the original retained patch remains unchanged.

### AC-06 Hierarchy conflicts fail before retention
Ancestor/descendant target combinations across retained and current-generation patches are deterministically rejected with `TARGET_HIERARCHY_CONFLICT`; no source mutation occurs.

### AC-07 Combined safe preflight is required for convergence
A work unit is not marked complete merely because one or more patches pass individually. The combined retained plus new proposal must pass the unchanged full safe validator.

### AC-08 Combined rejection preserves only prior proven intent
When newly safe patches cause combined preflight failure, those current-generation additions are discarded, prior retained safe patches remain unchanged, and the next bounded generation receives a sanitized combined rejection reason.

### AC-09 No-progress exhaustion remains finite
Generations that produce no new safe patch or fail combined preflight consume the existing admitted-agent recovery sequence. Distinct-agent exhaustion plus the existing one final validator repair still terminates without increasing any retry or timeout budget.

### AC-10 Final candidate still requires BUILD/TEST/VERIFY
A converged proposal must still pass disposable protected BUILD, TEST and VERIFY and independent evaluation before selection. Incremental preflight evidence cannot substitute for these stages.

### AC-11 Final source mutation authority is unchanged
Only the existing final `SafeImplementationEngine.apply()` plus source-lineage gateway may mutate/accept canonical source. Partial retained patches never write canonical files or transition the Engineering Run.

### AC-12 Durable diagnostics remain bounded
Persisted candidate rejection/convergence evidence contains only fixed reason codes, bounded counts/identities and explicit false authority flags. Raw model output, source text, generated content, provider payloads and arbitrary exception messages are absent.

### AC-13 Existing safety regressions remain green
Traversal, secrets, symlinks, unsupported extensions, stale source, collision, new nested parent handling, aggregate limits and target hierarchy protections remain unchanged and pass existing protected tests.

### AC-14 Existing model and recovery budgets are unchanged
Luna/Terra/Sol roster, 60-second hosted timeout, distinct-agent recovery count, final validator-repair count, request-level autonomy budget and zero hidden provider retries remain unchanged.

### AC-15 Protected release gates pass
Focused P2-V0.23.27 tests, full API regression, client checks, protected promotion evaluation, Bounded Autonomy Pilot, Workstream Spec Validation and required DSPy compile/verify pass on the exact reviewed head.

### AC-16 Exact production deployment is healthy
After merge, the exact application source reaches READY on the production API, canonical `/health` and `/ready` return HTTP 200 with database/providers ready, and runtime warning/error/fatal verification is clean.

### AC-17 Authenticated real run progresses beyond all-or-nothing IMPLEMENT admission
A user-authenticated retry of Engineering Run `3a1ba66a-5649-42b6-81ee-91684fe06bbc` or equivalent exact work either enters BUILD after incremental proposal convergence or exposes a later bounded blocker. A repeated generic whole-proposal safe-validator exhaustion without retained convergence evidence fails this acceptance criterion.
