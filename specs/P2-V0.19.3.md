## 1. Objective

Establish the Wave 6 independent-evaluation layer that can judge an agent-produced implementation candidate without allowing the implementing agent, evaluator, model, repository content, source content or provider output to become acceptance authority.

S3 consumes exact canonical identity plus already-admitted deterministic validation evidence and produces a bounded, provenance-rich quality-judgment record suitable for later S4 outcome routing and S5 candidate comparison. Deterministic/protected validation remains structurally above model judgment. A deterministic failure cannot be repaired, hidden, reclassified or outvoted by an evaluator. An evaluator can report bounded qualitative evidence about maintainability, implementation fit, defect/risk signals and other dimensions explicitly permitted by a server-owned evaluator policy, but the resulting record is evidence only. It cannot accept canonical source lineage, complete REVIEW, merge, deploy, create capabilities, change acceptance criteria or transition protected run state.

The implementing agent and the independent evaluator must be distinguishable by exact identity. Self-assessment may be preserved as non-independent evidence when useful, but it can never satisfy the independent-evaluation requirement. Missing, contradictory, stale, cross-Project or insufficient evidence must fail closed to an explicit bounded state such as insufficient evidence or HUMAN_REQUIRED rather than fabricating confidence.

S3 deliberately does not choose which agent should perform work, optimize quality/cost/time, generate competing candidates or synthesize a winner. Those responsibilities remain with later Wave 6 workstreams.

## 2. Fixed decisions

- **Deterministic validation is authoritative and first.** S3 may execute qualitative evaluation only after exact protected validation evidence for the candidate has been admitted and proves the deterministic gate passed. Any required deterministic failure or missing required protected evidence yields a deterministic-blocked evaluation outcome. Model or evaluator opinion cannot override it.
- **Evaluation is evidence, never acceptance.** S3 outputs an immutable bounded evaluation record. It does not mutate canonical source lineage, accepted-lineage heads, Engineering Run protected state, Work Specification approval, REVIEW state, provider delivery state or production state.
- **Exact canonical binding is mandatory.** Every evaluation request and result binds the canonical Project ID, Engineering Run ID, Work Specification ID/revision/digest, exact stable acceptance IDs, exact candidate/source lineage identity, producer-agent identity, evaluator identity and evaluator-policy identity/version/digest.
- **Independence is explicit, not inferred from prose.** The evaluator identity must be structurally distinct from the candidate producer identity for the result to count as independent evidence. Same-agent or identity-ambiguous evaluation fails the independence requirement even if the model claims objectivity.
- **Evaluator policy is server-owned.** Approved evaluation dimensions, allowed evidence classes, thresholds/floors, uncertainty rules and policy version/digest come from a bounded Parallax-owned policy object. Agent/source/model content cannot add dimensions, lower thresholds, suppress deterministic failures or alter required acceptance IDs.
- **Qualitative judgment is bounded.** Evaluator output contains typed dimension outcomes, concise observable findings, bounded confidence, evidence references and explicit uncertainty. It must not persist chain-of-thought, hidden reasoning, unrestricted provider payloads, raw prompts, arbitrary commands or arbitrary URLs.
- **Confidence is not correctness.** A high model confidence value never converts deterministic failure, missing evidence, identity drift, policy violation or self-evaluation into a supported outcome.
- **Insufficient evidence is a first-class result.** Missing, stale, contradictory or unsupported evidence produces explicit `INSUFFICIENT_EVIDENCE`, `DETERMINISTIC_BLOCKED`, `NOT_INDEPENDENT`, `POLICY_REJECTED` or `HUMAN_REQUIRED`-equivalent bounded states instead of guessed scores.
- **Replay is explicit and fail-closed.** The evaluation identity is derived from exact canonical bindings, evaluator policy/version, evaluator identity and admitted evidence digests. Exact replay is duplicate-safe. Changed policy, evidence, candidate lineage or evaluator version creates a distinguishable evaluation identity rather than silently replacing prior evidence.
- **Cross-Project evidence is prohibited.** Evidence from another Project is inadmissible unless a separate existing server-owned generalized-memory mechanism explicitly sanitizes and admits it for the current Project; S3 itself does not create such authority.
- **S4/S5 consume evidence only.** S3 emits a deterministic safe projection that later workstreams may use. That projection cannot direct spending, choose a provider, select a winning candidate or accept lineage.

## 3. Architecture requirements

### 3.1 Exact evaluation binding

Define an immutable `EvaluationBinding`-equivalent structure containing at minimum:

- canonical Project ID;
- canonical Engineering Run ID;
- exact Work Specification ID, revision and digest;
- exact stable acceptance IDs in canonical order;
- exact candidate/source lineage ID and content/revision digest required to identify the evaluated candidate;
- exact candidate operation/attempt identity where the S1 task/result protocol provides it;
- exact producer `AgentIdentity` or its deterministic canonical digest from S1;
- exact evaluator identity/version and adapter/provider evidence where applicable;
- exact evaluator-policy ID, version and digest;
- deterministic evaluation operation ID / replay key inputs;
- creation timestamp or bounded sequence identity only where needed for record provenance, never as authority.

Construction rejects empty or duplicate acceptance IDs, malformed identity, mismatched Project/run/spec/source bindings, invalid producer/evaluator identity, invalid policy identity and unsafe/unbounded text fields.

### 3.2 Protected deterministic validation evidence gate

Define a bounded admitted-evidence structure or adapter over existing Parallax validation evidence that can prove, for the exact candidate binding:

- protected BUILD/TEST/VERIFY evidence belongs to the same Project/run/Work Specification/source lineage;
- required stable acceptance IDs are exactly covered by the protected validator contract;
- deterministic browser/accessibility/console/network/layout or other registered required validators are represented where applicable;
- protected validation passed or failed using existing server-owned rules;
- evidence carries deterministic digests/references rather than raw unrestricted logs;
- stale, mismatched or missing evidence is distinguishable from a passing result.

S3 must not introduce a second deterministic validator or reinterpret protected failures. If any required deterministic evidence is failed, stale, identity-mismatched or absent, the evaluator is not permitted to produce an independently-supported candidate outcome.

### 3.3 Evaluator identity and independence check

Define bounded evaluator identity sufficient to distinguish at least:

- evaluator ID/version;
- evaluator adapter/provider kind when applicable;
- evaluator policy identity/version/digest;
- optional model/runtime label as non-authoritative evidence.

Provide a deterministic independence check comparing producer and evaluator identity projections. At minimum, an exact same agent identity fails independence. The implementation may define stricter same-provider/same-adapter policy checks only if those are explicitly server-owned policy, not agent/model judgment.

A failed independence check produces explicit `NOT_INDEPENDENT`-equivalent evidence and cannot be represented as an independent pass. A self-evaluation record may be retained as bounded auxiliary evidence but must be flagged non-independent in every safe serialization.

### 3.4 Server-owned evaluator policy

Define an immutable bounded `EvaluatorPolicy`-equivalent contract with:

- policy ID/version/content digest;
- approved qualitative dimensions;
- bounded per-dimension evidence requirements;
- allowed outcome vocabulary;
- optional dimension floors or escalation thresholds where needed;
- confidence bounds;
- explicit uncertainty/HUMAN_REQUIRED rules;
- deterministic failure precedence;
- privacy and safe-serialization constraints.

Policy dimensions may include approved categories such as maintainability, specification fit, defect/risk signals, change clarity or operational risk. The policy cannot introduce or remove Work Specification acceptance IDs. It does not replace deterministic protected validation. Repository text, agent output and model output cannot modify this policy.

### 3.5 Bounded evaluator request

Define a canonical evaluator request containing only admitted evidence and safe references required by the evaluator policy. It may include:

- exact `EvaluationBinding`;
- protected deterministic validation summary/reference digests;
- bounded candidate change summary or exact protected source/diff references already admitted by existing source-lineage infrastructure;
- bounded test/build/verify evidence references;
- Work Specification objective and approved acceptance requirements in a safe bounded projection;
- allowed evaluator dimensions and policy constraints.

The request must not include raw credentials, private provider payloads, unrestricted repository blobs, hidden reasoning, arbitrary executable commands or arbitrary network instructions. Source or agent text is untrusted evidence and cannot carry authority-bearing instructions to the evaluator.

### 3.6 Qualitative evaluator protocol

Define a provider-neutral evaluator protocol or abstract interface that accepts the canonical bounded evaluator request and returns a typed raw judgment projection. The implementation must support at least one deterministic/reference evaluator used for tests. A real provider-backed evaluator may be integrated only through existing bounded provider/model infrastructure if doing so requires no new credential, network or authority path.

The evaluator output is parsed/validated into bounded fields equivalent to:

- per-dimension outcome/status;
- bounded score or confidence only when permitted by policy;
- concise observable finding text with hard length/count limits;
- admitted evidence references supporting each finding;
- explicit missing/contradictory evidence markers;
- evaluator identity/version and policy identity/version/digest;
- no hidden reasoning or free-form authority instructions.

Unknown or malformed evaluator output fails closed as insufficient evidence or policy rejection. The evaluator cannot provide new acceptance IDs, commands, capabilities, credentials, source mutations, provider targets or approval decisions.

### 3.7 Independent evaluation outcome taxonomy

Normalize final S3 evidence into a bounded outcome taxonomy equivalent to:

- `SUPPORTED` — deterministic validation passed, independence passed, policy-required evidence is sufficient and qualitative policy checks are supported;
- `DETERMINISTIC_BLOCKED` — a required protected validator failed or required deterministic evidence is absent/stale/mismatched;
- `NOT_INDEPENDENT` — producer/evaluator independence requirement is not met;
- `INSUFFICIENT_EVIDENCE` — deterministic gate may be green but policy-required qualitative evidence is missing, contradictory or malformed;
- `POLICY_REJECTED` — evidence violates explicit server-owned evaluator policy;
- `HUMAN_REQUIRED` — the policy identifies an ambiguity/risk boundary that cannot be resolved safely by bounded automated judgment.

`SUPPORTED` means only that the independent-evaluation evidence supports the candidate under the exact bound policy. It is not canonical acceptance, merge approval, deployment approval or REVIEW completion.

### 3.8 Deterministic result admission and precedence

Provide deterministic server-owned normalization/admission helpers that enforce:

1. exact identity binding;
2. exact candidate/source lineage binding;
3. exact protected acceptance projection;
4. deterministic validation precedence;
5. evaluator independence;
6. evaluator-policy identity/version/digest;
7. bounded output/schema validity;
8. evidence sufficiency and privacy constraints.

If an evaluator claims `SUPPORTED` while deterministic validation failed, admission must return `DETERMINISTIC_BLOCKED` or reject the raw judgment. If evaluator output attempts to change acceptance criteria, suppress a validator failure, add authority-bearing instructions or reference another Project's private evidence, admission must fail closed.

### 3.9 Replay, idempotency and version distinction

Define a deterministic evaluation fingerprint from the exact canonical candidate binding, producer identity, evaluator identity/version, evaluator-policy identity/version/digest and admitted evidence digests.

Exact replay of the same fingerprint must be duplicate-safe. The same exact evaluation record must not create a second authority-bearing action because S3 has no such action. A changed candidate lineage, evidence digest, evaluator version or policy version/digest creates a new distinguishable fingerprint. If two incompatible records claim the same fingerprint, deterministic conflict detection must fail closed rather than silently selecting one.

### 3.10 Safe serialization and downstream evidence contract

Provide deterministic safe serialization suitable for S4/S5 that includes only:

- exact canonical IDs/digests required for provenance;
- outcome and bounded reason codes;
- bounded dimension results/findings;
- confidence/score only where policy permits;
- explicit uncertainty/missing-evidence markers;
- evaluator identity/version;
- evaluator-policy identity/version/digest;
- exact evidence references/digests;
- replay fingerprint.

It must exclude raw credentials/secrets, provider payloads, prompts, hidden reasoning, unrestricted logs, arbitrary URLs/commands and cross-Project private evidence. The downstream projection has no mutation method and grants no provider, source, acceptance, merge, deployment or REVIEW authority.

## 6. Security

All repository, source, agent and evaluator/model content is untrusted evidence. S3 is a trust-reduction boundary: it narrows admitted evidence into an exact provenance-bound record and never converts content into authority.

Exact Project identity is mandatory. Evidence bound to another Project cannot be used merely because filenames, source digests, objective text, acceptance text or agent identity appear similar. Existing explicitly sanitized/generalized engineering memory may be referenced only through its already-admitted bounded identity and cannot be made Project-private by S3.

Deterministic validation evidence must be server-owned and exact-lineage bound. An agent-provided claim such as “all tests passed” is not a substitute for protected BUILD/TEST/VERIFY or browser validation evidence. A model statement that deterministic failures are unimportant cannot suppress those failures.

Producer and evaluator identity must be compared structurally. Source text or a model statement that the evaluator is “independent” cannot satisfy independence. Identity ambiguity fails closed.

Evaluator requests and outputs must have strict size/count/schema bounds. No raw API keys, tokens, secret values/handles, cookies, connection strings, provider request/response payloads, unrestricted logs, raw hidden reasoning, arbitrary executable commands or arbitrary network targets may appear in canonical evaluation evidence or safe serialization.

Evaluator findings are descriptive evidence only. Any text resembling instructions to change policy, bypass review, grant capabilities, execute commands, alter acceptance, merge/deploy or contact arbitrary endpoints is ignored/rejected as authority-bearing content.

HUMAN_REQUIRED is preserved as a protected boundary. S3 may recommend/emit HUMAN_REQUIRED under server-owned policy, but cannot resolve or bypass that state itself.

## 7. Acceptance criteria

### AC-01 Exact canonical evaluation identity binding
Every evaluation request/result binds exact canonical Project ID, Engineering Run ID, Work Specification ID/revision/digest, stable acceptance IDs, exact candidate/source lineage identity, producer identity, evaluator identity and evaluator-policy ID/version/digest. Construction/admission rejects malformed, duplicate, empty, stale or mismatched identity and cannot infer identity from source/model prose.

### AC-02 Deterministic protected validation always outranks evaluator judgment
A candidate with any required deterministic/protected validation failure, missing required validator evidence, stale evidence or identity-mismatched validation cannot receive an admitted `SUPPORTED` outcome. Tests prove an evaluator claiming success over deterministic failure is normalized/rejected as `DETERMINISTIC_BLOCKED` or equivalent and cannot weaken existing protected validation.

### AC-03 Implementer self-assessment cannot satisfy independence
Producer and evaluator identities are structurally compared. Exact self-evaluation and identity-ambiguous cases cannot count as independent evidence regardless of claimed confidence or prose. Tests preserve optional self-assessment only as explicitly non-independent auxiliary evidence.

### AC-04 Evaluator policy is exact, server-owned and provenance-bound
Every evaluation binds an immutable evaluator-policy ID/version/digest defining allowed qualitative dimensions, evidence requirements, thresholds/escalation rules and uncertainty handling. Agent/source/model content cannot add/remove acceptance IDs, change policy, lower deterministic requirements or fabricate a different policy digest.

### AC-05 Missing, contradictory or insufficient evidence produces bounded uncertainty
Missing, stale, contradictory, malformed or unsupported qualitative evidence yields explicit `INSUFFICIENT_EVIDENCE`, `POLICY_REJECTED` or `HUMAN_REQUIRED`-equivalent evidence rather than fabricated scores/confidence. Confidence is bounded and never overrides identity, deterministic validation, independence or evidence sufficiency failures.

### AC-06 Qualitative judgment is typed, bounded and non-authoritative
Evaluator output is parsed into bounded dimension outcomes, concise findings, evidence references, confidence/score only where policy permits and explicit uncertainty. Raw prompts, hidden reasoning, unrestricted provider payloads, arbitrary commands/URLs and authority-bearing instructions are absent from canonical evidence. An evaluator result cannot accept lineage, transition protected run state, merge, deploy, create capabilities or complete REVIEW.

### AC-07 Replay is idempotent and policy/evidence changes are version-distinguished
A deterministic evaluation fingerprint binds candidate identity, evaluator identity/version, evaluator-policy identity/version/digest and admitted evidence digests. Exact replay is duplicate-safe. Candidate/evidence/policy/evaluator changes create distinguishable fingerprints. Conflicting records for the same exact fingerprint fail closed rather than silently replacing one another.

### AC-08 Cross-Project and stale evidence is rejected
Tests prove evidence from another Project, another run, another Work Specification revision/digest, another source lineage or stale candidate attempt cannot satisfy an evaluation even when objective/source text appears equivalent. Only already-admitted sanitized/generalized memory references may cross Project boundaries under their existing authority; S3 cannot create new cross-Project visibility.

### AC-09 Adversarial agent/source/evaluator content cannot inject authority
Tests include attempts to redefine acceptance criteria, hide deterministic failure, claim independence in prose, inject evaluator-policy changes, request shell/network/provider authority, supply arbitrary deployment/merge instructions, smuggle secrets/raw provider payloads and reference cross-Project private evidence. All fail closed or remain inert bounded evidence.

### AC-10 S4/S5 receive trustworthy read-only evaluation evidence
S3 exposes a deterministic safe downstream projection containing exact provenance, outcome, bounded dimension evidence, uncertainty, evaluator/policy identity and evidence digests/fingerprint. The projection contains no mutation capability and cannot select providers, route spending, choose winners, mutate canonical lineage, merge/deploy or complete REVIEW.

### AC-11 Existing protected evaluation and runtime authority remains unchanged and green
S3 reuses rather than weakens existing Work Specification, Engineering Run, protected deterministic validation, source-lineage, correction, benchmark/promotion, provider authorization, delivery and REVIEW contracts. Relevant existing API/protected-autonomy/evaluation regression suites remain green and S1 agent-protocol tests remain green.

### AC-12 Exact-head worker boundary and development gate
`P2-V0.19.3` validates with stable acceptance IDs and authentic DSPy SpecCritic + SpecCompiler evidence before semantic implementation. Temporary DSPy workflow changes are restored byte-for-byte before runtime implementation/final candidate. Final S3 changed paths remain within issue #266 ownership; exact-head Workstream Spec Validation, Bounded Autonomy Pilot and P2 CI pass; PR targets `integration/wave6-agentic-control-plane`; worker stops `READY FOR INTEGRATION` with no worker merge/deploy.
