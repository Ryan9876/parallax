## 1. Objective

Allow an authenticated browser that cannot create a WebGL context to enter Parallax's existing functional reduced-graphics workspace rather than crashing after session restoration.

## 2. Fixed decisions

- Web clients must test WebGL context creation before loading or mounting Skia.
- A failed context test uses the existing `FallbackApp`; it does not alter Google or QA password authentication, session cookies, API authorization, provider configuration, database state, or access roles.
- The normal WebGL-capable path continues to load Skia and render its existing graphics.
- The reduced-graphics path must mount no Skia canvas and preserve ordinary conversation, Build plan, and Engineering Run access.
- The failure is handled at the web entrypoint before the signed-in application mounts; no runtime exception from a Skia canvas may be required to activate fallback.

## 3. Scope

Owned paths:

- `apps/client/index.web.tsx`;
- `apps/client/scripts/visual-smoke.mjs`;
- this specification.

No API, schema, provider, package, or authentication file changes are allowed.

## 4. Non-goals

- Replacing the normal graphical experience for WebGL-capable clients.
- Changing Google SSO, QA password enrollment, cookie/session behavior, access roles, Supabase configuration, or server authorization.
- Adding a server route, schema migration, provider credential, feature flag, browser fingerprinting, or permanent device setting.
- Retrying, bypassing, or suppressing an authentication failure.

## 5. Security and reliability requirements

- The capability test is browser-local, contains no credential or user data, and does not persist a token, capability result, or identifier.
- A failed WebGL test must fail closed to the existing static/reduced-graphics client, never to an unauthenticated or privileged surface.
- No Skia canvas is mounted after a failed test, so the original WebGL creation exception is not used as flow control.
- The check is guarded for non-browser execution and treats an exception as graphics unavailable.

## 6. Acceptance criteria

### AC-01 WebGL-capable web remains graphical
On a browser that can create a WebGL context, the client follows the existing Skia load path and existing visual acceptance still proves the graphical workspace mounts canvases.

### AC-02 WebGL-unavailable web fails before Skia mount
On a browser whose canvas cannot create a WebGL context, the web entrypoint selects the existing functional reduced-graphics application before a Skia `Canvas` mounts. No uncaught `Could not create a WebGL context` error is emitted.

### AC-03 Authenticated experience remains available
The normal WebAuthRoot and server-issued Parallax session continue unchanged; after access restoration, the reduced-graphics workspace remains usable for conversation, Build plan, and Engineering Run information.

### AC-04 No authority expansion
The change adds no credential handling, sign-up, session bypass, server route, provider configuration, database mutation, source acceptance, deployment authority, or lifecycle authority.

### AC-05 Deterministic coverage
The visual smoke launches a browser with WebGL disabled, proves WebGL is unavailable, proves the functional reduced-graphics workspace mounts no canvas, and reports no browser error. Existing normal-graphics and CanvasKit-unavailable fallback checks remain green.

### AC-06 Session restoration is unchanged
The existing signed HttpOnly Parallax session is still checked by `WebAuthRoot` before either the normal application or reduced-graphics application mounts.

### AC-07 Existing fallback remains functional
The existing CanvasKit-unavailable smoke continues to prove conversation streaming, Build plan, amendment handling, and plain-language reduced-graphics state.

### AC-08 Failure output is bounded
The client does not expose WebGL driver data, browser internals, account data, credentials, or raw exception text to the ordinary product surface.
