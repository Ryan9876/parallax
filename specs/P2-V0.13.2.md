# Parallax 2.0 — P2-V0.13.2

Status: Approved implementation specification
Date: 2026-08-22

## Objective

Restore the intended v0.13 visual experience on the current production-capable mainline without regressing bounded-autonomy behavior: deploy the approved 3D interlocking-knot identity, make Ambient Chroma Flow visibly animated during ordinary use, and carry forward the validated workspace/composer polish that was stranded on the earlier visual branch.

## Problem

The bounded-autonomy release was promoted from a branch that did not contain the separately developed identity/workspace polish. Production therefore still renders the old aperture logo and an Ambient Chroma Flow whose nested time multipliers are so slow that it appears static during normal use. The older visual branch is now stale and conflicts with the autonomy mainline, so it must not be merged wholesale.

## Requirements

1. Port only the validated visual/UI changes from the stale identity-workspace branch onto the current mainline.
2. Preserve the v0.13 bounded-autonomy coordinator, Engineering Run controls, API behavior, authentication, persistence, and authority boundaries unchanged.
3. Replace the old aperture/circle mark with the approved transparent 3D interlocking-knot identity everywhere Parallax identity is rendered.
4. The knot uses slow ambient rotation and restrained traveling highlight on supported web surfaces; reduced motion uses the same static knot.
5. Ambient Chroma Flow must show perceptible frame/composition change during a normal 5–15 second observation while remaining calm and reading-safe.
6. Preserve the visual branch fixes for response-follow behavior, measured composer clearance, compact optical engraving, and rounded Work Specification material.
7. Browser acceptance must explicitly prove that the knot renders and that idle frames change over time.
8. No new runtime dependency, API endpoint, database migration, autonomous source-editing authority, Git merge authority, or production-deployment authority is introduced by this patch.

## Acceptance criteria

- Production and release-browser tests render at least one `Parallax animated knot mark`.
- The old circular aperture identity is no longer used by `ParallaxLogo`.
- Two idle screenshots captured roughly one second apart differ, proving visible motion is active.
- Reduced-motion behavior remains static and semantically equivalent.
- Work Specification uses rounded optical material without the prior heavy peach left rule.
- Active streamed responses stay above the composer and use the compact optical engraving head.
- TypeScript, Expo web export, browser/Skia acceptance, API regression, protected Engineering/Reason/Code evaluation, and bounded-autonomy tests remain green.
- The resulting production deployment is verified before this release is recorded as deployment-verified.

## Risks

- Reapplying a stale visual branch could overwrite autonomy work. Mitigation: port only known visual blobs/files that do not own the autonomy state machine or API execution path.
- Faster ambient motion could become distracting. Mitigation: preserve low-frequency broad-field motion and the darker reading-zone mask; tests only require perceptibility, not high speed.
- Mobile web could expose layout regressions from the composer/workspace polish. Mitigation: retain the existing compact breakpoint and browser acceptance across phone/tablet/desktop viewports.

## Non-goals

- Expanding autonomous implementation beyond the current IMPLEMENT boundary.
- Redesigning the product beyond the previously approved v0.13 identity/workspace polish.
- Changing the active product-context baseline from P2-V0.13.0.
