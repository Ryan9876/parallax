# Parallax 2.0 — P2-V0.13.1

Status: Approved implementation specification
Date: 2026-08-22

## Objective

Make the first bounded-autonomy production test unambiguous and safe by preventing a stale production environment override from binding newly created conversations to an older Parallax product specification.

## Problem

The validated v0.13.0 application and API are deployed to production, but newly created production conversations are still reporting `P2-V0.5.0`. The repository default is `P2-V0.13.0`, so the production `PARALLAX_ACTIVE_SPEC_ID` environment override is stale and currently wins over the release default. This makes the UI appear unchanged and can bind new work to obsolete product context even though the v0.13 bounded-autonomy code is live.

## Requirements

1. Production must never allow `PARALLAX_ACTIVE_SPEC_ID` to regress below the active specification baseline compiled into the release.
2. A valid environment value equal to or newer than the compiled baseline remains permitted so deliberate forward configuration is still possible.
3. Development and test environments retain explicit older-spec overrides for regression and compatibility testing.
4. Invalid specification identifiers must continue to fail validation.
5. Existing bounded-autonomy authority boundaries remain unchanged: no autonomous source editing, Git merge, or production deployment authority is added.
6. The fix must be covered by deterministic tests.

## Acceptance criteria

- With `PARALLAX_ENV=production`, repository baseline `P2-V0.13.0`, and `PARALLAX_ACTIVE_SPEC_ID=P2-V0.5.0`, resolved active spec is `P2-V0.13.0`.
- With `PARALLAX_ENV=production` and `PARALLAX_ACTIVE_SPEC_ID=P2-V0.14.0`, resolved active spec is `P2-V0.14.0`.
- With `PARALLAX_ENV=test` and `PARALLAX_ACTIVE_SPEC_ID=P2-V0.5.0`, resolved active spec remains `P2-V0.5.0`.
- Invalid values still raise `ValueError`.
- Full API regression suite remains green.
- After production deployment, a newly created conversation reports at least `P2-V0.13.0`.

## Risks

- Masking a stale production environment variable can make configuration drift less visible. Mitigation: record the discovered drift in `CURRENT-STATE.md` and keep the environment override behavior deterministic and bounded to regression prevention.
- Version parsing errors could select the wrong baseline. Mitigation: parse only the already-enforced `P2-Vx.y.z` format and compare numeric tuples.

## Non-goals

- Redesigning the Code workspace.
- Expanding autonomous implementation authority.
- Changing authentication, Work Specification approval, or Engineering Run state-machine semantics.
