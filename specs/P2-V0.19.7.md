## Objective

Add a provider-neutral, configuration-driven model routing layer that can prefer a local model endpoint for eligible Parallax inference work, preserve protected validation, and automatically fall back to the existing hosted GPT-5.6 escalation chain without creating a second authority path or weakening Wave 6 governance.

## Requirements

- Local-first routing is opt-in and server-owned; default production behavior remains unchanged unless explicitly configured.
- A local provider entry binds model identity, endpoint, optional API key slot, provider kind and eligibility metadata without exposing credentials to callers, prompts, source packages or logs.
- Model routing order is configuration-driven and validated at startup; malformed, duplicate or unsupported entries fail closed.
- Local models may be attempted before hosted models, but protected validation remains authoritative and a valid local result may stop escalation.
- Local provider unavailability or provider failure advances to the next admitted route without changing acceptance requirements.
- Protected-output validation failure may advance to the next admitted route; no route may reinterpret acceptance criteria or waive protected validators.
- Existing hosted Vercel AI Gateway request-scoped OIDC behavior and canonical GPT-5.6 identities remain unchanged.
- Global `DSPY_API_BASE` / `DSPY_API_KEY` remains an explicit operator override and is not repurposed as the local-first provider registry.
- Routing diagnostics record model identity, provider kind, status and bounded duration/error class without logging endpoint credentials or raw provider payloads.
- Local-first configuration must not grant network, shell, source mutation, provider spending, GitHub/Vercel, approval, REVIEW or release authority.
- Tests cover local success, local unavailable -> hosted fallback, local validation failure -> hosted fallback, configuration rejection, credential non-logging, hosted gateway preservation and default-production compatibility.
- The implementation must remain isolated from Wave 6 release integration until Control Tower records the exact deployment-verified Wave 6 production baseline and explicitly authorizes reconciliation.

## Acceptance Criteria

- AC-01: With no local-first configuration, runtime model order and hosted transport behavior are byte-for-byte semantically equivalent to the existing accepted GPT-5.6 Luna -> Terra -> Sol route.
- AC-02: A validated server-owned route configuration can place one admitted local model before the existing hosted GPT-5.6 chain without changing caller-visible authority or protected acceptance semantics.
- AC-03: Each configured route resolves its own provider transport; configuring a local endpoint does not redirect hosted GPT-5.6 models away from the Vercel AI Gateway.
- AC-04: A successful local-model result that passes the existing protected validator stops escalation and records bounded route evidence.
- AC-05: Local provider failure or unavailability advances to the next admitted route and preserves sanitized failure classification/evidence.
- AC-06: Local output rejected by protected validation advances to the next admitted route; no validation bypass or threshold weakening is introduced.
- AC-07: Malformed, duplicate, caller-controlled, credential-bearing or unsupported route configuration fails closed before model execution.
- AC-08: Request-scoped Vercel OIDC remains the only automatic hosted-production GPT-5.6 credential path; local route credentials/endpoints are server-owned and never logged or persisted in route evidence.
- AC-09: Existing explicit `DSPY_API_BASE` / `DSPY_API_KEY` behavior remains deliberate operator override compatibility and is not silently combined with the provider registry.
- AC-10: Focused tests prove default compatibility, local-first success/fallback/validation behavior, per-provider transport isolation, credential redaction and no authority expansion.
- AC-11: Exact-head required gates pass on the isolated worker branch and the PR remains draft/DO NOT MERGE.
- AC-12: Before any integration, the branch is reconciled to the exact deployment-verified Wave 6 production SHA and fresh full relevant gates are rerun; no deployment claim is made from isolated development evidence.

## Non-Scope

- no Wave 6 release modification;
- no production environment change;
- no public exposure of a local inference endpoint;
- no automatic production tunnel creation;
- no arbitrary caller-supplied model endpoints;
- no replacement of deterministic/protected validation with model judgment;
- no merge, production promotion or REVIEW bypass;
- no billing, multi-user provider management or generic plugin marketplace.

## Security and operational constraints

Local inference endpoints are trusted only as bounded model transports, never as authority. Production-hosted Parallax must not assume `localhost` reaches an operator machine. Any future remote connection to a private inference node requires an authenticated private transport design and separate deployment authorization. This workstream only establishes routing/transport abstractions and local/co-located development support.

## Rollback

Because the feature is opt-in, rollback is configuration removal plus code rollback to the accepted parent. Default behavior must remain the existing hosted route when local-first configuration is absent.
