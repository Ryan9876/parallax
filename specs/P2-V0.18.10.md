# Parallax 2.0 — Vercel AI Gateway Request-Scoped OIDC Stabilization

Workstream: issue #284 corrective revision

## 1. Objective

Correct the failed P2-V0.18.9 production transport assumption so hosted DSPy model traffic reaches Vercel AI Gateway deterministically with the same request-scoped Vercel OIDC identity already required by Parallax production runtime boundaries, while preserving canonical Parallax model identities, Luna -> Terra -> Sol order, explicit development overrides, local/CI behavior, sanitized provider-failure handling, and all existing Project, Work Specification, source-lineage, REVIEW and release authority.

## 2. Production evidence driving this revision

The first P2-V0.18.9 release passed constructor tests, exact-head CI, production build preflights, `/health` and `/ready`, but failed its required authenticated Capture Spec smoke. Production `POST /v1/conversations/121ba8c2-3d6b-445b-be8e-7ed3e62bac71/work-specifications/draft` returned HTTP 429 on deployment `dpl_C5sdDZgnwq8uSKFkA7DkJc4rCW82`; Luna, Terra and Sol each ended in sanitized `LMRateLimitError` and LiteLLM reported the underlying provider as `openai`.

P2-V0.18.9 attempted to infer hosted Gateway transport inside `build_lm` from process environment, including `VERCEL_OIDC_TOKEN`, and rewrote canonical model names into LiteLLM's `vercel_ai_gateway/...` namespace. That was insufficient for the deployed Functions runtime. Existing Parallax production architecture already distinguishes build-time `VERCEL_OIDC_TOKEN` from the request-scoped Functions identity carried by `x-vercel-oidc-token`: production runtime must not fall back to the build-time environment token.

Vercel's OpenAI-compatible AI Gateway API accepts Gateway authentication at `https://ai-gateway.vercel.sh/v1` while preserving provider/model identifiers such as `openai/gpt-5.6-sol`. P2-V0.18.10 therefore binds the network endpoint explicitly and carries only a validated request-scoped production OIDC token (or an explicit server-owned Gateway API key) into DSPy construction.

## 3. Scope

- preserve `ModelRouter.MODEL_ORDER` canonical identities and Luna -> Terra -> Sol order;
- preserve explicit `DSPY_API_BASE` / `DSPY_API_KEY` as the highest-priority deliberate operator/development override;
- reuse the existing production `runtime_vercel_oidc_token` request-header contract rather than creating a second runtime OIDC mechanism;
- in production request paths that construct DSPy programs, validate `x-vercel-oidc-token` and pass the resulting opaque credential explicitly through bounded coordinator/program composition;
- otherwise allow explicit server-owned Gateway API keys from `AI_GATEWAY_API_KEY` or `VERCEL_AI_GATEWAY_API_KEY` in deterministic precedence;
- when Gateway authentication is available, keep the canonical `openai/gpt-5.6-*` model ID and invoke DSPy/LiteLLM with `api_base=https://ai-gateway.vercel.sh/v1` plus the resolved Gateway credential;
- production must fail closed when neither a valid request-scoped OIDC credential nor an explicit server-owned Gateway API key/explicit DSPY override exists; it must not silently route to direct OpenAI;
- preserve existing direct-provider/local behavior only outside production when neither an explicit DSPY override nor Gateway authentication exists;
- remove reliance on the `vercel_ai_gateway/...` namespace for the hosted OIDC path introduced by P2-V0.18.9;
- cover all production DSPy request paths, including conversation scope/reason, Work Specification drafting, and protected implementation generation, rather than correcting only Capture Spec;
- add deterministic tests proving exact Gateway base URL selection, request-token propagation, credential precedence, explicit override precedence, canonical model identity preservation, production fail-closed behavior, non-production fallback and secret safety;
- retain existing sanitized `RoutingFailureKind` semantics and user-visible recovery behavior;
- document the corrected endpoint/OIDC contract in `services/api/.env.example` without storing a credential.

## 4. Non-goals

- adding Anthropic, Google, local or other production fallback models;
- changing Luna -> Terra -> Sol order or canonical model IDs;
- changing OpenAI, Vercel or user billing/credit/budget settings;
- exposing raw provider responses, credentials, OIDC tokens, prompts or hidden reasoning;
- changing provider retry counts or adding unbounded retry/fan-out;
- creating a caller-supplied or model-supplied provider endpoint;
- changing the existing production request-OIDC validation rules except for reusing them for model transport;
- changing Project, Work Specification, Engineering Run, source-lineage, approval, REVIEW/HUMAN_REQUIRED, merge or production authority;
- changing Wave 6 agent-control-plane semantics.

## 5. Security and authority

Gateway endpoint selection is server-owned and constant. User, model, repository or agent content cannot supply the provider endpoint, credential, provider namespace or token. Credentials may only be admitted from the validated request-scoped runtime identity or explicit server-owned environment configuration and must never enter model prompts, logs, traces, persisted evidence, client responses, source packages or sandboxes.

Production Functions must use the validated request-scoped `x-vercel-oidc-token` path already established by `runtime_vercel_oidc_token`; build-time/process-environment `VERCEL_OIDC_TOKEN` is not a production runtime fallback. Missing or malformed production request OIDC fails closed unless a separately explicit server-owned Gateway API key or DSPY override is configured.

Explicit `DSPY_API_BASE` / `DSPY_API_KEY` remains a deliberate trusted operator/development override and takes precedence over automatic Gateway selection so local Ollama and governed CI continue to function. Automatic hosted selection must not replace an explicit endpoint.

The Gateway endpoint is an internal transport detail. Canonical `ModelRouter` identity remains `openai/gpt-5.6-*`; protected routing evidence and Work Specification model identity do not change merely because transport uses the Vercel AI Gateway endpoint.

## 6. Acceptance criteria

### AC-01 Production request-scoped OIDC Gateway selection is deterministic
For a production request with a valid `x-vercel-oidc-token` and no explicit DSPY override or Gateway API key, the validated request credential is passed into DSPy construction; `build_lm("openai/gpt-5.6-terra", ...)` preserves that canonical model string and passes `api_base="https://ai-gateway.vercel.sh/v1"` plus the opaque request token as LM authentication.

### AC-02 Build-time OIDC is not production runtime authority
Automatic production model transport must not read or rely on process-environment `VERCEL_OIDC_TOKEN`. A production request missing valid request-scoped OIDC and lacking an explicit server Gateway key/DSPY override fails closed instead of silently selecting direct OpenAI.

### AC-03 Canonical model identity and order are preserved
`ModelRouter.MODEL_ORDER` remains exactly `openai/gpt-5.6-luna`, `openai/gpt-5.6-terra`, `openai/gpt-5.6-sol`; Gateway transport selection does not rewrite those externally recorded identities.

### AC-04 Explicit DSPY override remains authoritative
If `DSPY_API_BASE` or `DSPY_API_KEY` is explicitly configured, `build_lm` uses the explicit values and does not substitute the Vercel Gateway endpoint, even when Gateway credentials or request-scoped OIDC are also available.

### AC-05 Gateway credential precedence is bounded
Without an explicit DSPY override, explicit server-owned Gateway API keys resolve deterministically as `AI_GATEWAY_API_KEY` then `VERCEL_AI_GATEWAY_API_KEY`; if neither exists, a validated request-scoped OIDC credential may be used. No other source can grant model-provider authentication.

### AC-06 Non-production no-credential behavior remains compatible
Outside production, when no explicit DSPY override, Gateway API key or admitted request credential exists, Parallax preserves existing direct-provider/local development behavior and does not fabricate credentials or provider authority.

### AC-07 Secret-safe construction
Focused tests prove Gateway keys/OIDC tokens are passed only into the LM constructor/provider boundary and never appear in public/canonical model identity, routing traces, persisted evidence, logger messages, exception text or source-controlled examples.

### AC-08 Existing local DSPy development remains compatible
The credential-free local DSPy/Ollama path using explicit `DSPY_API_BASE` continues to execute without Gateway substitution, and authentic SpecCritic + SpecCompiler development evidence remains possible.

### AC-09 Failed P2-V0.18.9 adapter assumption is not retained
The automatic hosted Gateway path no longer depends on rewriting canonical models to `vercel_ai_gateway/...`; deterministic tests reject reintroduction of the namespace-only OIDC assumption.

### AC-10 All production DSPy entry points receive the same transport authority
Conversation scope/reason, Work Specification drafting, and protected implementation generation use one bounded Gateway transport contract derived from the request-scoped production identity/server-owned configuration; none may silently fall back to a different provider path in production.

### AC-11 Existing failure and protected-runtime semantics remain unchanged
`RoutingFailureKind`, sanitized `AttemptRecord`, Work Specification recovery semantics, authentication, Project/repository binding, Work Specification approval, Engineering Run state, source lineage, tools, provider delivery, protected evaluation, REVIEW/HUMAN_REQUIRED and deployment authority remain unchanged and existing regressions stay green.

### AC-12 Governed release and production proof
The authentic compiled DSPy plan passes `--require-dspy`; exact worker-head Workstream Spec Validation, Bounded Autonomy and P2 CI pass; merge uses expected-head protection; production API promotion is bound to an exact release identity; post-cutover authenticated Capture Spec succeeds, `/health` and `/ready` are HTTP 200, and exact-deployment runtime logs show no model-capacity failure for that smoke before `CURRENT-STATE.md` is reconciled and #284 is closed.
