# Parallax 2.0 — Vercel AI Gateway OIDC Endpoint Stabilization

Spec ID: P2-V0.18.10
Status: APPROVED FOR IMPLEMENTATION
Date: 2026-08-27
Workstream: issue #284 corrective revision
Base: `74a027a69dbc6f983e2023e9e5367f2d5fd0bd7b`

## 1. Objective

Correct the failed P2-V0.18.9 production transport assumption so hosted DSPy model traffic reaches Vercel AI Gateway deterministically when Gateway authentication is available, including Vercel OIDC, while preserving canonical Parallax model identities, Luna -> Terra -> Sol order, explicit development overrides, local/CI behavior, sanitized provider-failure handling, and all existing Project, Work Specification, source-lineage, REVIEW and release authority.

## 2. Production evidence driving this revision

The first P2-V0.18.9 release passed constructor tests, exact-head CI, production build preflights, `/health` and `/ready`, but failed its required authenticated Capture Spec smoke. Production `POST /v1/conversations/121ba8c2-3d6b-445b-be8e-7ed3e62bac71/work-specifications/draft` returned HTTP 429 on deployment `dpl_C5sdDZgnwq8uSKFkA7DkJc4rCW82`; Luna, Terra and Sol each ended in sanitized `LMRateLimitError` and LiteLLM reported the underlying provider as `openai`.

Vercel documents two relevant contracts: its LiteLLM ecosystem adapter uses the `vercel_ai_gateway/...` model namespace with `VERCEL_AI_GATEWAY_API_KEY`, while its OpenAI-compatible Gateway API accepts either an AI Gateway API key or `VERCEL_OIDC_TOKEN` at `https://ai-gateway.vercel.sh/v1`. P2-V0.18.10 removes dependency on ambiguous adapter credential inference for the hosted OIDC path by binding the network endpoint explicitly.

## 3. Scope

- preserve `ModelRouter.MODEL_ORDER` canonical identities and Luna -> Terra -> Sol order;
- preserve explicit `DSPY_API_BASE` / `DSPY_API_KEY` as the highest-priority deliberate operator/development override;
- otherwise, when Gateway authentication is available, keep the canonical `openai/gpt-5.6-*` model ID and invoke DSPy/LiteLLM with `api_base=https://ai-gateway.vercel.sh/v1` plus the resolved Gateway credential/OIDC token;
- resolve Gateway authentication in deterministic server-owned precedence: `AI_GATEWAY_API_KEY`, then `VERCEL_AI_GATEWAY_API_KEY`, then `VERCEL_OIDC_TOKEN`;
- preserve existing direct-provider/local behavior when neither an explicit DSPy override nor Gateway authentication exists;
- remove reliance on the `vercel_ai_gateway/...` namespace for the OIDC transport path introduced by P2-V0.18.9;
- add deterministic tests proving exact Gateway base URL selection, credential precedence, explicit override precedence, canonical model identity preservation, no-credential fallback and secret safety;
- retain existing sanitized `RoutingFailureKind` semantics and user-visible recovery behavior;
- document the corrected endpoint contract in `services/api/.env.example` without storing a credential.

## 4. Non-goals

- adding Anthropic, Google, local or other production fallback models;
- changing Luna -> Terra -> Sol order or canonical model IDs;
- changing OpenAI, Vercel or user billing/credit/budget settings;
- exposing raw provider responses, credentials, OIDC tokens, prompts or hidden reasoning;
- changing provider retry counts or adding unbounded retry/fan-out;
- creating a generic caller-supplied provider endpoint;
- changing Project, Work Specification, Engineering Run, source-lineage, approval, REVIEW/HUMAN_REQUIRED, merge or production authority;
- changing Wave 6 agent-control-plane semantics.

## 5. Security

Gateway endpoint selection is server-owned and constant. User, model, repository or agent content cannot supply the provider endpoint, credential, provider namespace or token. Credentials may only be read from process environment at the provider-construction boundary and must never enter model prompts, logs, traces, persisted evidence, client responses, source packages or sandboxes.

Explicit `DSPY_API_BASE` / `DSPY_API_KEY` remains a deliberate trusted operator/development override and must take precedence over automatic Gateway selection so local Ollama and governed CI continue to function. Automatic hosted selection must not replace an explicit endpoint.

The Gateway endpoint is an internal transport detail. Canonical `ModelRouter` identity remains `openai/gpt-5.6-*`; protected routing evidence and Work Specification model identity do not change merely because transport uses the Vercel AI Gateway endpoint.

## 6. Acceptance criteria

### AC-01 Production OIDC Gateway endpoint selection is deterministic
When no explicit DSPY override exists and `VERCEL_OIDC_TOKEN` is present, `build_lm("openai/gpt-5.6-terra")` preserves that canonical model string and passes `api_base="https://ai-gateway.vercel.sh/v1"` plus the OIDC token as the LM credential.

### AC-02 Canonical model identity and order are preserved
`ModelRouter.MODEL_ORDER` remains exactly `openai/gpt-5.6-luna`, `openai/gpt-5.6-terra`, `openai/gpt-5.6-sol`; Gateway transport selection does not rewrite those externally recorded identities.

### AC-03 Explicit DSPY override remains authoritative
If `DSPY_API_BASE` or `DSPY_API_KEY` is explicitly configured, `build_lm` uses the explicit values and does not substitute the Vercel Gateway endpoint, even when Gateway credentials/OIDC are also present.

### AC-04 Gateway credential precedence is bounded
Without an explicit DSPY override, Gateway authentication resolves deterministically in this order: `AI_GATEWAY_API_KEY`, then `VERCEL_AI_GATEWAY_API_KEY`, then `VERCEL_OIDC_TOKEN`.

### AC-05 No credential fabrication
If no explicit DSPY override and no Gateway credential/OIDC token exists, Parallax preserves existing direct-provider/local behavior and does not invent a credential or Gateway endpoint.

### AC-06 Secret-safe construction
Focused tests prove resolved API keys/OIDC tokens are passed only into the LM constructor and never appear in public/canonical model identity, logs, serialized routing evidence or source-controlled examples.

### AC-07 Existing local DSPy development remains compatible
The credential-free local DSPy/Ollama path using explicit `DSPY_API_BASE` continues to execute without Gateway substitution, and authentic SpecCritic + SpecCompiler development evidence remains possible.

### AC-08 Failed P2-V0.18.9 adapter assumption is not retained
The automatic hosted Gateway path no longer depends on rewriting canonical models to `vercel_ai_gateway/...`; tests fail if OIDC selection relies on that namespace instead of the explicit Gateway base URL.

### AC-09 Existing failure semantics remain unchanged
`RoutingFailureKind`, sanitized `AttemptRecord`, Work Specification 429 behavior and response-stream recovery semantics remain unchanged; only provider transport construction changes.

### AC-10 Environment contract is documented
`services/api/.env.example` documents optional API-key/OIDC Gateway authentication and the server-owned Gateway endpoint behavior with empty example values only.

### AC-11 Protected runtime authority remains unchanged
Authentication, Project/repository binding, Work Specification approval, Engineering Run state, source lineage, tools, provider delivery, protected evaluation, REVIEW/HUMAN_REQUIRED and deployment authority remain unchanged and existing regressions stay green.

### AC-12 Governed release and production proof
The authentic compiled DSPy plan passes `--require-dspy`; exact worker-head Workstream Spec Validation, Bounded Autonomy and P2 CI pass; merge uses expected-head protection; production API promotion is bound to an exact release identity; post-cutover authenticated Capture Spec succeeds, `/health` and `/ready` are HTTP 200, and exact-deployment runtime logs show no model-capacity failure for that smoke before `CURRENT-STATE.md` is reconciled and #284 is closed.
