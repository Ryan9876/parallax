## 1. Objective

Correct the source-delivery classification exposed after the production-accepted P2-V0.23.41 REVIEW rework. A repository whose canonical default ref exists and points to a commit with the canonical empty Git tree is commit-bearing and therefore already has a valid branch base. It must not be treated as a truly empty repository requiring Parallax's deterministic two-commit greenfield initializer.

The change must preserve the strict P2-V0.23.37–P2-V0.23.39 canonical greenfield baseline contract for repositories that are truly empty or already contain the exact Parallax baseline. It must not rewrite default-branch history, accept arbitrary missing trees, or broaden Git/provider authority.

## 2. Production finding and confirmed root cause

P2-V0.23.41 is production-accepted on exact API source `78b408a2323ab474c3183a64d55c6399f5b20402`. Frozen W9-S1 Engineering Run `a64d56b7-ad42-42ad-9562-891783363f4a` accepted bounded REVIEW findings for `AC-03` and `AC-05`, re-entered PLAN from REVIEW revision 6, invalidated the prior selected candidate, regenerated from accepted lineage `src:da5d0fb62d34a3228bb56e7a7d82971c8023a536d11944ba71bcaa51a407b871`, accepted replacement lineage `src:001736ab731e243956cf78ede7a0087d2b81595f1008568850eac1e9acc3e809`, passed BUILD/TEST/VERIFY, and returned to REVIEW revision 12 with `last_failure_code=null`.

The later REVIEW publication attempt failed independently as event sequence 31:

- provider: GitHub;
- action: `repository.initialize-empty`;
- result: `GREENFIELD_BASELINE_MISMATCH`;
- run remained REVIEW revision 12.

The exact target state is commit-bearing. `Ryan9876/parallax-qa1/main` points to commit `b24c029be916f8b1f0ab07347a988f814cc8d567`, message `Remove temporary P2-V0.23.40 acceptance baseline`, whose exact tree SHA is the universal Git empty tree `4b825dc642cb6eb9a060e54bf8d69288fbee4904`.

The root cause is confirmed in `GreenfieldVerifiedLineageDelivery.deliver()`: whenever the accepted lineage descends from a durable `greenfield` root, delivery unconditionally invokes `initialize_empty_baseline()`. `GreenfieldGitHubClient.initialize_empty_baseline()` interprets any existing default-branch head as a purported Parallax canonical baseline and calls `_verify_baseline()`. An ordinary commit-bearing empty head therefore fails `GREENFIELD_BASELINE_MISMATCH` even though it is already a valid Git branch base.

## 3. Fixed repository-state classification

Source delivery must distinguish exactly these states server-side:

1. **TRUE_EMPTY** — canonical repository exists, but no usable default-branch head exists. Existing `repository.initialize-empty` behavior remains mandatory and unchanged.
2. **PARALLAX_CANONICAL_BASELINE** — the existing default head is the exact deterministic Parallax cleanup commit, including exact cleanup message, actor identity rules, canonical empty tree, one exact bootstrap parent, exact bootstrap marker/blob/provenance, and unchanged default ref. Existing strict read-only baseline verification remains mandatory and unchanged.
3. **COMMIT_BEARING_EMPTY** — the canonical default ref exists, the referenced commit is read successfully, its exact tree SHA is the canonical Git empty-tree SHA, and it is not admitted as a Parallax canonical-baseline candidate. The exact current head becomes the ordinary branch base for bounded accepted-source publication. No initializer/default-ref mutation occurs.
4. **COMMIT_BEARING_NONEMPTY** — the canonical default ref exists and its head tree is not the canonical empty tree. A durable `greenfield` root may not silently retarget publication onto this changed repository state; delivery fails closed.

Any malformed repository/default-ref/commit response, missing exact identity, ambiguous state, concurrent default-ref movement, or tree mismatch fails closed.

## 4. Canonical-baseline preservation rule

P2-V0.23.42 must not let an invalid or tampered Parallax-looking baseline fall through to the generic COMMIT_BEARING_EMPTY path.

If the existing empty-tree head presents the fixed Parallax cleanup message `Finalize Parallax empty greenfield baseline`, delivery must require the complete existing `_verify_baseline()` proof. Failure of any actor/message/parent/bootstrap/tree/blob/provenance/default-ref invariant remains `GREENFIELD_BASELINE_MISMATCH`; it may not be reclassified as an ordinary empty commit.

An empty-tree head with any other ordinary commit message may be classified as COMMIT_BEARING_EMPTY after exact repository/ref/commit/tree verification and ref-stability read-back.

## 7. Reliability and concurrency

For any commit-bearing repository classification, the server must:

1. read the canonical repository and exact default branch;
2. read the exact default ref/head;
3. read the exact referenced commit and its tree SHA;
4. classify the tree only by exact canonical empty-tree SHA versus non-empty tree SHA;
5. re-read the exact default ref before returning the inspected base;
6. require the head to remain unchanged.

Concurrent movement fails closed before branch publication. Existing branch creation and commit mutation continue to use the exact base revision returned by this classification, so later GitHub branch-base conflicts remain protected by existing provider read-back and conflict handling.

No clock/timing heuristic or eventual-consistency sleep is introduced.

## 8. Acceptance criteria

### AC-01 True-empty behavior unchanged
A repository with no usable default-branch head still uses the existing deterministic two-commit Parallax initializer and exact non-force default-ref update.

### AC-02 Canonical baseline replay unchanged
An exact existing Parallax two-commit baseline is still fully verified, read-only, and reused as the branch base. No canonical invariant is weakened.

### AC-03 Tampered canonical-looking baseline fails closed
An empty-tree head with the fixed Parallax cleanup message but wrong actor, parent, bootstrap marker/blob/provenance, or ref identity fails `GREENFIELD_BASELINE_MISMATCH` and is never treated as an ordinary empty commit.

### AC-04 Commit-bearing empty repository is admitted without initialization
An ordinary existing default-branch commit whose exact tree SHA is `4b825dc642cb6eb9a060e54bf8d69288fbee4904` is used directly as the branch base. `repository.initialize-empty` is not invoked and the default branch is not mutated.

### AC-05 Commit-bearing non-empty drift fails closed
If a run with a durable greenfield root reaches delivery after the target default branch has become non-empty, publication fails before branch/commit/PR mutation rather than silently rebasing onto unrelated source.

### AC-06 Exact repository/ref/commit/tree identity is mandatory
Malformed/missing repository metadata, default branch, ref object, head SHA, commit payload, tree SHA, or mismatched repository identity fails closed.

### AC-07 Concurrent default-ref movement fails closed
If the default ref changes between initial inspection and classification read-back, delivery fails before accepted-source publication.

### AC-08 Ordinary accepted-source delivery remains unchanged after base selection
For an admitted commit-bearing-empty base, Parallax still creates only the bounded feature branch, commits the exact accepted lineage, creates/reads the PR, creates/reads a Vercel Preview, persists the delivery record, and remains at REVIEW.

### AC-09 Replay/idempotency remains exact
An already persisted successful delivery record for the same run/accepted lineage replays without additional provider mutation. Existing branch/PR/Preview idempotency semantics are unchanged.

### AC-10 No authority expansion
Tests and diff prove no new provider permission, credential, network, model, command, execution profile, source-lineage, force-ref, merge, production, or automatic REVIEW authority.

### AC-11 Protected release gates pass
The exact spec passes validation plus authentic DSPy SpecCritic/SpecCompiler and strict compiled-plan validation before semantic implementation. Focused tests, full API regression, Bounded Autonomy, Workstream Spec Validation, and P2 CI pass on exact reviewed heads.

### AC-12 Production acceptance
Exact merged API source reaches production READY with normal preflights, `/health` and `/ready` HTTP 200 and reviewed exact-deployment runtime scans. The same frozen W9-S1 run at REVIEW revision 12 retries publication of replacement lineage `src:001736ab731e243956cf78ede7a0087d2b81595f1008568850eac1e9acc3e809` against the commit-bearing-empty `parallax-qa1/main` without `GREENFIELD_BASELINE_MISMATCH`, creates/reads the bounded delivery artifacts or reuses them idempotently, and remains at human REVIEW.
