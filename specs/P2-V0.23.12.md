# Parallax 2.0 — Pre-Resume State Snapshot Correction

Status: APPROVED FOR IMPLEMENTATION — SPEC-FIRST
Spec ID: P2-V0.23.12
Date: 2026-08-30
Workstream: #474
Architecture: v3.25 (unchanged)

## Objective

Correct the P2-V0.23.11 `/resume` route so the human-authorized terminal-worker re-arm decision is based on the Engineering Run state that existed before the resume mutation, rather than on a live ORM object that may be mutated in-place by the same SQLAlchemy session.

## Production evidence

Engineering Run `2b3cd15f-c5e2-481a-8266-c92c6534b08b` produced persisted sequence `#29 RUN_CONTROL / RESUMED` followed directly by `#30 IMPLEMENT / FAILED` after P2-V0.23.11 was deployed. P2-V0.23.11 requires an intervening worker recovery observation when a FAILED run is explicitly resumed, but no `HUMAN_RESUME_RECOVERING` worker event was emitted.

The route currently stores `prior = svc.get(run_id)`, then calls `svc.resume(...)` using the same session, and only afterward evaluates `prior.state`. Because SQLAlchemy identity-map semantics may mutate or refresh the same `EngineeringRun` object during `resume`, `prior.state` can already be `IMPLEMENT` by the time the condition executes. The authorization predicate is therefore skipped even though the request began from durable `FAILED` state.

## Required correction

1. Read and snapshot the scalar pre-mutation run state before invoking `svc.resume`.
2. Use only that immutable scalar snapshot when deciding whether P2-V0.23.11 `prepare_human_resume` is authorized.
3. Preserve the existing postcondition that the resumed run must no longer be `FAILED`.
4. Add a route-level regression with a deliberately identity-aliased mutable run object so the test fails under the old implementation and passes only when the pre-mutation scalar state is captured.
5. Preserve all existing worker recovery, lease-generation, candidate, source-lineage, provider, deployment, and REVIEW boundaries.

## Non-goals

- No automatic retry after terminal failure.
- No new worker generation without explicit human resume.
- No migration or persistence-schema change.
- No client/UI change.
- No provider, repository, source mutation, deployment, or REVIEW authority expansion.
- No architecture revision; Architecture v3.25 already defines the intended durable rule.

## Acceptance

- Focused route regression passes.
- Existing worker-recovery tests pass.
- Full API regression passes.
- Protected client/browser, promotion, DSPy, and Bounded Autonomy release gates remain green.
- After production deployment, the same affected Engineering Run is retried explicitly once. Production acceptance requires a persisted worker recovery event after `RUN_CONTROL / RESUMED` and evidence that autonomous dispatch proceeds past the prior terminal-worker conflict.
