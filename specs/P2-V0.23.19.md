## 1. Objective

Complete the two-phase production-QA repository cutover established by P2-V0.23.17. Now that the exact `Ryan9876/parallax-qa` workflow has authenticated against production and both routine source-only acceptance paths have reached REVIEW with verified source handoff, remove the temporary `Ryan9876/parallax` QA workflow identities and workflow files so standing production-QA trust has one dedicated repository boundary.

## 2. Fixed decisions

- Standing production-QA trust is exactly repository `Ryan9876/parallax-qa`, GitHub repository ID `1351817336`, workflow `Ryan9876/parallax-qa/.github/workflows/production-replay.yml@refs/heads/main`.
- The two migration-only `Ryan9876/parallax` workflow tuples are retired and must fail authentication after this release.
- The application-repository workflow files `.github/workflows/qa-production-replay.yml` and `.github/workflows/w8-s2-qa-replay.yml` are removed because routine production replay now belongs to `parallax-qa`.
- The existing signed OIDC issuer, `parallax://qa-production` audience, `refs/heads/main` ref, GitHub-hosted runner requirement, admitted event set, bounded run-id validation, and bounded QA account mapping remain unchanged.
- Authorization remains an exact server-owned `(repository, repository_id, workflow_ref)` tuple. There is no repository-name-only, repository-ID-only, workflow-only, prefix, glob, substring, actor-only, branch-only, or event-only trust.
- Existing reusable test scripts may remain in the application repository when they are useful engineering harnesses; deleting standing workflow identities does not require deleting non-authoritative test utilities.
- No normal-user authentication, Project ownership, Work Specification identity, Engineering Run state transition, source-lineage authority, model routing, worker recovery, Git mutation, deployment, production promotion, or REVIEW completion authority changes.

- Deleting historical evidence or rewriting Git history merely because a workflow identity is retired.

## 5. Security and reliability

The migration safety expansion in P2-V0.23.17 was intentionally temporary. Keeping old application-repository QA identities after the dedicated repository path is proven would preserve unnecessary authentication surface and contradict the staged cutover contract. This release therefore contracts the allowlist rather than adding new authority.

A token from either retired application workflow must fail closed even if its issuer, audience, repository name, repository ID, main ref, hosted runner, event, and run ID are otherwise valid. Only the complete dedicated repository tuple is accepted. The verifier continues to validate the signed standard claims before tuple admission and exposes no token, cookie, raw JWT claim set, provider payload, or user credential as durable evidence.

Rollback may restore the prior exact tuples and workflow files if dedicated QA authentication fails unexpectedly, but rollback must not introduce wildcard trust or bypass repository-ID binding. No database, source-lineage, Project, Work Specification, or Engineering Run migration is involved.
