## 1. Objective

Define a typed, project-scoped, read-only-first Playwright-backed browser capability layer that can collect trustworthy application evidence for Parallax without introducing arbitrary browsing, JavaScript, network, credential or destructive-action authority.

The browser layer composes the existing tool-authority registry and protected browser/visual validation principles. It does not create an unrestricted agent browser or replace deterministic protected validation.

## 2. Fixed decisions

- v1 is non-destructive/read-only by capability contract.
- Browser actions are server-owned typed capabilities; callers/models cannot submit arbitrary commands or JavaScript.
- Navigation targets are server-admitted exact origins/URLs or exact Preview references derived from canonical Project/run/provider evidence.
- Redirects leaving the admitted origin/target policy fail closed.
- Credential extraction, password manager access, cookies/auth-token export and arbitrary header/environment injection are forbidden.
- Purchases, form submissions that mutate external state, deletion, account changes and other destructive actions are outside v1.
- Browser evidence is secondary to deterministic protected validation and cannot convert deterministic failure into success.
- Every evidence item binds exact Project/run/source/Preview context where applicable.
- Browser sessions are isolated, bounded in actions/time/pages/output and destroyed after use.
- No raw page dumps, unrestricted screenshots or full network bodies are persisted by default; only bounded admitted evidence is retained.
- Any future mutating browser capability requires a separate specification, explicit capability identity and approval semantics.

## 3. Architecture requirements

### 3.1 Capability registry

Define immutable tool capabilities for a minimal v1 set such as:

- `browser.navigate_admitted`;
- `browser.inspect_dom`;
- `browser.inspect_accessibility`;
- `browser.capture_screenshot`;
- `browser.assert`.

Exact names may be reconciled to the current registry, but capability semantics must remain typed and narrow.

### 3.2 Admitted target resolution

Browser target resolution occurs only after canonical authenticated Project/run resolution. Accepted targets may come from exact server-owned Preview/provider evidence, explicitly registered test origins or other server-owned allowlist policy. User/model/repository text cannot grant a new origin.

### 3.3 Redirect/network boundary

Navigation and subresource policy must preserve the accepted target/origin/network restrictions. Unexpected redirect to an unadmitted origin fails closed. The browser layer does not provide generic HTTP fetch or arbitrary proxying.

### 3.4 Session isolation

Each invocation/session is ephemeral and Project/run/context bound. Browser state is not reused across Projects. Session cleanup is mandatory on success, failure and timeout.

### 3.5 DOM/accessibility inspection

Inspection returns bounded normalized evidence: selected semantic nodes/roles/names/states, accessibility findings and deterministic assertions. Full unbounded DOM/page source is not canonical evidence.

### 3.6 Screenshot evidence

Screenshot capture binds exact target/context, viewport and evidence digest and reuses existing screenshot/privacy policy where applicable. Evidence is bounded and never treated as source acceptance or production-deployment proof.

### 3.7 Typed assertions

Assertions are declarative and allowlisted, such as element/role presence, visible text match within bounded rules, URL/origin expectation, accessibility property or layout-safe predicate. Arbitrary JavaScript/eval selectors that execute attacker-controlled code are forbidden.

### 3.8 Credential and sensitive-data handling

The browser tool cannot request, serialize or return passwords, access tokens, cookies, authorization headers, secret environment values or raw credential-store data. Sensitive detected content is redacted/unavailable under existing policy.

### 3.9 Result/evidence contract

Results distinguish `SUCCEEDED`, `FAILED`, `DENIED`, timeout and bounded policy rejection. Failure/denial is never represented as success. Evidence includes exact capability/request/context identity, bounded findings, timing and digests without raw sensitive payloads.

### 3.10 Audit and replay

Tool authorization/result/audit records reuse the current project-scoped tool authority model. Replaying an exact read-only request may reproduce equivalent evidence but cannot acquire broader capability or mutate external state.

## 4. Scope

Specification/security design may proceed before S1 acceptance. Semantic scope after dependency acceptance may include a narrow browser adapter, typed capability registration, admission/policy layer, safe result normalization and focused tests. Existing protected browser validation should be reused rather than duplicated where practical.

## 5. Non-goals

- arbitrary URL browsing;
- arbitrary JavaScript/eval;
- unrestricted HTTP/network access;
- credential entry/extraction or secret-bearing automation;
- purchases, destructive form submissions, account changes or deletion;
- generic web scraping service;
- browser-based source mutation;
- provider administration, merge/deploy or REVIEW authority;
- weakening existing browser/accessibility/console/network/layout validation.

## 6. Acceptance criteria

### AC-01 Typed registered capabilities only
Every browser action resolves through an immutable registered v1 capability; unknown/arbitrary actions are denied before browser execution.

### AC-02 Canonical Project/run target binding
Browser requests bind authenticated canonical Project/run/context and server-owned admitted target identity; cross-Project or caller-invented target authority fails closed.

### AC-03 Origin/redirect fail-closed policy
Navigation to or redirect toward an unadmitted origin is denied without exposing generic network authority.

### AC-04 No arbitrary JavaScript
The public/internal capability contract provides no arbitrary script/eval surface; assertions are declarative and allowlisted.

### AC-05 Credential isolation
Tests prove credentials, cookies, authorization headers, password-store data and server secret environment values cannot be requested or serialized as browser evidence.

### AC-06 Non-destructive v1
Tests prove v1 exposes no capability for purchases, destructive submissions, deletion, account changes or other external-state mutation.

### AC-07 Bounded DOM/accessibility evidence
DOM/accessibility inspection is normalized and bounded; full unbounded page/DOM payload is not retained as canonical evidence.

### AC-08 Provenance-bound screenshots
Screenshot evidence binds exact context/target/viewport/digest and preserves existing privacy/redaction policy.

### AC-09 Deterministic validation precedence
Browser evidence cannot override failed protected deterministic validation for the same candidate/source context.

### AC-10 Session isolation and cleanup
Sessions are ephemeral, Project-bound, bounded in resource/action/time use and reliably destroyed on success/failure/timeout; state cannot leak across Projects.

### AC-11 Denial/failure truthfulness
Policy denial, browser error and timeout are distinct bounded outcomes and can never be serialized as success.

### AC-12 No authority expansion
Browser v1 grants no source acceptance, Engineering Run lifecycle, arbitrary network, provider administration, merge/deploy, approval or REVIEW completion authority.
