# Parallax 2.0 — Vercel AI Gateway Provider Boundary Stabilization

Spec ID: P2-V0.18.9
Status: APPROVED FOR IMPLEMENTATION
Date: 2026-08-26
Workstream: issue #284
Base: `c87d5ec6b2c59a983d1b97f1d4f61d2e02808e5c`

## 1. Objective

Route production DSPy model traffic through Vercel AI Gateway deterministically instead of relying on LiteLLM's direct OpenAI provider path, while preserving canonical Parallax model identities, Luna -> Terra -> Sol order, explicit development overrides, local/CI behavior, sanitized provider-failure handling, and all existing Project, Work Specification, source-lineage, REVIEW and release authority.

## 2. Scope

- make Vercel AI Gateway the preferred hosted provider boundary when a Gateway credential or Vercel deployment OIDC token is available;
- preserve the public/canonical model IDs already used by `ModelRouter` and persisted routing evidence;
- translate only the internal DSPy/LiteLLM invocation model into the documented `vercel_ai_gateway/<provider>/<model>` namespace;
- resolve Gateway authentication from `AI_GATEWAY_API_KEY`, `VERCEL_AI_GATEWAY_API_KEY`, or `VERCEL_OIDC_TOKEN` using deterministic server-owned precedence;
- preserve explicit `DSPY_API_BASE` / `DSPY_API_KEY` as the highest-priority deliberate override for governed development, CI, local Ollama and controlled alternate endpoints;
- preserve existing direct-provider/local behavior when neither an explicit DSPy override nor Gateway authentication is present;
- add focused deterministic tests for routing selection, credential precedence, canonical identity preservation, explicit override precedence and safe secret handling;
- update the API environment example to document the production Gateway path without storing a real credential;
- retain existing sanitized `RoutingFailureKind` semantics and user-visible recovery behavior.

## 3. Non-goals

- adding Anthropic, Google, local or other production fallback models;
- changing Luna -> Terra -> Sol order or canonical model IDs;
- changing OpenAI, Vercel or user billing/credit/budget settings;
- exposing raw provider responses, credentials, OIDC tokens, prompts or hidden reasoning;
- changing provider retry counts or adding unbounded retry/fan-out;
- changing Project, Work Specification, Engineering Run, source-lineage, approval, REVIEW/HUMAN_REQUIRED, merge or production authority;
- changing Wave 6 agent-control-plane semantics.

## 4. Security

Gateway selection is server-owned runtime configuration. User, model, repository or agent content cannot supply a provider endpoint, credential, provider namespace or authentication token. Credentials may only be read from process environment at the provider-construction boundary and must never enter model prompts, logs, traces, persisted evidence, client responses, source packages or sandboxes.

Explicit `DSPY_API_BASE` / `DSPY_API_KEY` remains a deliberate trusted operator/development override and must take precedence over automatic Gateway selection so local Ollama and governed CI continue to function. Automatic hosted selection must not silently replace an explicit endpoint.

The Gateway mapping is an internal transport detail. Canonical `ModelRouter` identity remains `openai/gpt-5.6-*`; protected routing evidence and Work Specification model identity do not change merely because transport moves through Vercel AI Gateway.

## 5. Acceptance criteria

### AC-01 Production Gateway selection is deterministic
When no explicit DSPy endpoint override exists and `VERCEL_OIDC_TOKEN` is present, `build_lm("openai/gpt-5.6-terra")` invokes DSPy/LiteLLM through the Vercel AI Gateway provider namespace rather than the direct OpenAI provider path.

### AC-02 Canonical model identity is preserved
`ModelRouter.MODEL_ORDER` and externally recorded model identity remain the existing canonical `openai/gpt-5.6-luna`, `openai/gpt-5.6-terra`, `openai/gpt-5.6-sol` sequence; only the internal LM transport model is remapped.

### AC-03 Explicit DSPy override remains authoritative
If `DSPY_API_BASE` or `DSPY_API_KEY` is explicitly configured, `build_lm` preserves the caller-selected model plus those explicit endpoint/authentication values and does not auto-remap to Vercel AI Gateway.

### AC-04 Gateway credential precedence is bounded
Without an explicit DSPy override, Gateway authentication resolves deterministically in this order: `AI_GATEWAY_API_KEY`, then `VERCEL_AI_GATEWAY_API_KEY`, then `VERCEL_OIDC_TOKEN`.

### AC-05 No credential fabrication
If no explicit DSPy override and no Gateway credential/OIDC token exists, Parallax preserves the existing direct-provider/local development behavior and does not invent, persist or log a credential.

### AC-06 Secret-safe construction
Tests prove resolved API keys/OIDC tokens are passed only to the LM constructor and are absent from returned/public model identities, routing records, logger messages and serialized evidence owned by this workstream.

### AC-07 Existing local DSPy development remains compatible
The credential-free local DSPy/Ollama path using explicit `DSPY_API_BASE` continues to execute without Gateway remapping, and authentic SpecCritic + SpecCompiler development evidence remains possible.

### AC-08 Existing failure semantics remain unchanged
`RoutingFailureKind`, sanitized `AttemptRecord`, Work Specification 429 behavior and response-stream recovery semantics remain unchanged except that successful hosted traffic now reaches the intended Gateway provider boundary.

### AC-09 Environment contract is documented
`services/api/.env.example` documents optional `AI_GATEWAY_API_KEY` / Vercel OIDC Gateway use and retains empty example values only; no real credential is committed.

### AC-10 Deterministic regression coverage
Focused API tests cover OIDC Gateway mapping, both API-key aliases, credential precedence, explicit override precedence, no-credential fallback, unchanged canonical model order and absence of secret leakage.

### AC-11 Protected runtime authority remains unchanged
Authentication, Project/repository binding, Work Specification approval, Engineering Run state, source lineage, tools, provider delivery, protected evaluation, REVIEW/HUMAN_REQUIRED and deployment authority remain unchanged and existing regressions stay green.

### AC-12 Governed release and production proof
The authentic compiled DSPy plan passes `--require-dspy`; exact worker-head Workstream Spec Validation, Bounded Autonomy and P2 CI pass; merge uses expected-head protection; production API promotion is bound to an exact release identity; post-cutover Capture Spec succeeds through Gateway and `/health`, `/ready` plus runtime-log checks are clean before `CURRENT-STATE.md` is reconciled and issue #284 is closed.
