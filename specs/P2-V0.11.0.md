# Parallax 2.0 v0.11.0 — Conversation Material & Optical Etching

Status: APPROVED FOR IMPLEMENTATION
Spec ID: P2-V0.11.0
Depends on: P2-V0.10.0
Method: spec-first visual refinement + exact-head release verification

## 1. Objective

Refine the core conversation experience so Parallax feels calmer, less conventionally boxed, and more distinct while preserving the Editorial Optical identity, Google identity boundary, durable Work Specifications, approved-spec execution binding, and all existing protected product behavior.

## 2. User outcome

Conversation becomes the visual center of the workspace. User and assistant messages use softly rounded translucent neutral-grey material without hard enclosing lines. The living surface gains a slow lava-lamp-like optical drift, and the active response restores a clearly visible theme-colored laser etching effect that cools into readable settled text.

## 3. Scope

- Replace conventional framed conversation boxes with lighter translucent material surfaces.
- Use soft rounded geometry and no continuous solid border around ordinary user/assistant messages.
- Keep speaker alignment and metadata clear without relying on heavy chrome.
- Preserve the existing Parallax logo and assistant identity row, but quiet its metadata hierarchy.
- Strengthen the active optical typesetter so fresh glyphs visibly read as etched violet/indigo light with a restrained cyan hot point.
- Preserve readable settled assistant text after inscription completes.
- Evolve the Skia living surface into a calm low-frequency lava-lamp field using slow organic violet/indigo/cyan masses rather than decorative particles or obvious looping motion.
- Maintain a darker reading field beneath narrative content.
- Preserve reduced-motion and reduced-graphics parity.
- Retune the composer to the same soft translucent material language without making it visually dominant.
- Preserve Google OAuth/authorization, Reason, Code, Work Specification, Engineering Run, persistence, SSE, and API behavior unchanged.

## 4. Conversation material contract

### User message

- right-aligned;
- translucent neutral-grey/indigo material;
- rounded corners, approximately 18–22 px in the production visual scale;
- no visible continuous outline;
- no bright glow;
- high-contrast selectable text;
- metadata quieter than message content.

### Assistant message

- left-aligned and wider than the user message without becoming a full-width dashboard panel;
- translucent neutral-grey/navy material;
- rounded corners, approximately 20–24 px;
- no conventional top/bottom/left box rules;
- may use a faint local violet optical bloom rather than a hard border;
- assistant identity row remains outside the material bubble;
- settled text remains selectable and accessibility-aware.

### Composer

- rounded translucent dark material;
- border presence reduced to an optical edge/shadow rather than a conventional field outline;
- primary send action remains obvious and accessible;
- mobile interaction targets remain at least 44 pt.

## 5. Ambient optical field contract

The background may evoke a calm lava lamp, but must remain product atmosphere rather than entertainment.

- use 3–5 large organic low-frequency fields;
- dominant colors remain deep violet, indigo, and midnight blue with very restrained cyan;
- movement cycles are slow and non-bouncy, roughly 20–45 seconds in perceived drift;
- fields deform and drift continuously without obvious reset points;
- no particles, sparkles, fast gradients, scanner grids, or bright neon blobs;
- center reading zone remains darker than the perimeter;
- activity may increase field energy only modestly;
- reduced motion freezes the field into a coherent static composition.

## 6. Optical etching contract

The active assistant response must visibly restore the laser-etching signature in the current theme.

- an optical head tracks the active wrapped line;
- new glyphs emerge with a violet/indigo etched edge and short-lived internal lavender energy;
- the freshest characters may carry a subtle cyan highlight at the active inscription point;
- the beam/head must read as precision inscription, not a scanning HUD;
- the hot tail lasts long enough to be perceptible on normal reading speed but cools quickly enough to avoid neon persistence;
- settled text cools to the normal pale narrative color;
- reduced motion reveals text normally and never hides content.

## 7. Accessibility

- narrative contrast remains WCAG-AA targeted against rendered material surfaces;
- no semantic state relies on animation or color alone;
- final assistant text remains selectable;
- reduced motion disables time-dependent inscription/background motion while preserving layout and meaning;
- reduced graphics removes Skia rendering while preserving message material hierarchy through normal React Native styles;
- motion intensity must not increase during idle conversation reading.

## 8. Security

v0.11.0 is a visual-only release and must preserve the complete v0.10.0 identity and authorization boundary.

- Google OAuth continues to use the existing PKCE flow and dedicated Supabase Auth broker.
- Authentication continues to be distinct from authorization; only active `authorized_users` identities receive Parallax access.
- Parallax browser sessions remain server-issued, signed, Secure, HttpOnly, SameSite=Lax, and host-only in production.
- Google/Supabase access credentials, Google client secret, Supabase service-role credentials, and the Parallax root bearer must never be introduced into visual code, client storage, logs, or repository history.
- Existing protected API routes remain protected and continue to require a valid identity-bearing Parallax session or the server-side break-glass bearer where explicitly supported.
- No visual effect, animation, reduced-graphics path, or mobile layout may bypass, weaken, or hide authentication/authorization state.
- The release introduces no schema, permission, tenancy, cookie, OAuth, CORS, or session-lifetime changes.

## 9. Acceptance criteria

### AC-01 Conversation boxes are no longer conventional panels
User and assistant messages no longer use hard continuous borders or rectangular dashboard-panel framing.

### AC-02 Soft translucent material
Both message types use rounded, translucent neutral-grey/navy material that remains visually distinct from the background without becoming opaque cards.

### AC-03 Assistant hierarchy
Assistant identity remains outside the response material and metadata remains subordinate to narrative copy.

### AC-04 Theme-colored optical etching
During an active response, freshly rendered glyphs visibly show violet/indigo optical etching with restrained cyan focus energy.

### AC-05 Settled readability
After inscription completes, assistant response text cools to normal high-contrast selectable text without persistent neon glare.

### AC-06 Calm lava field
The Skia workplane shows slow organic lava-lamp-like field drift with no particles, scanner grid, obvious bounce, or high-frequency shimmer.

### AC-07 Reading-field protection
The central conversation reading area remains darker than the moving perimeter fields and ambient effects never obscure narrative text.

### AC-08 Composer parity
The composer adopts the softer rounded material language while preserving keyboard, mobile, and send interaction behavior.

### AC-09 Reduced motion and reduced graphics
Reduced-motion and reduced-graphics modes preserve all content, controls, contrast, hierarchy, and semantic state without requiring animation.

### AC-10 Functional regression protection
Google identity/authorization, Reason, Code, SSE, durable conversations, Work Specifications, approved-spec execution binding, Engineering Runs, API protection, and persistence continue to pass existing tests.

### AC-11 Responsive behavior
Conversation width, spacing, bubbles, composer, and ambient rendering remain usable on mobile and desktop with no horizontal overflow or clipped message content.

### AC-12 Release verification
Specification validation, API tests, client typecheck/state tests, web export, browser/Skia acceptance, Google-auth browser acceptance, Code-binding browser acceptance, protected evaluation, DSPy release compilation, Vercel READY state, health/readiness, protected-route checks, and runtime-error checks pass before v0.11.0 is recorded as deployment-verified.

## 10. Non-goals

- New authentication or authorization behavior.
- API/schema/database changes.
- New conversation features, attachments, markdown editor behavior, or model controls.
- Replacing Editorial Optical with a new unrelated visual language.
- Continuous neon glow on all text.
- Decorative particles or game-like effects.
- Broader autonomous execution authority.

## 11. Risks and mitigations

- **Ambient motion distracts from reading:** keep large low-frequency fields, dark center bias, slow movement, and restrained opacity.
- **Laser effect becomes neon:** restrict high-energy treatment to fresh glyphs and active optical head; cool settled text quickly.
- **Removing borders harms message grouping:** preserve alignment, spacing, rounded translucent material, and speaker metadata.
- **Mobile density regresses:** cap message widths, preserve 44 pt controls, reduce padding proportionally, and validate mobile browser screenshots.
- **Visual-only release breaks protected behavior:** run the same full release gate and do not change backend contracts.

## 12. Release gate

Implementation is authorized by this specification. Production promotion requires exact-head release validation and production deployment evidence. `DESIGN-SYSTEM.md` must be updated because durable conversation-material and ambient-motion rules change. `CURRENT-STATE.md` changes only after verified production promotion. `ARCHITECTURE.md` and `PROJECT-CONSTITUTION.md` remain unchanged unless implementation reveals a durable architecture or governance change.
