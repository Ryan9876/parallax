# P2-V0.13.6 — iOS Keyboard-Visible Workspace

Status: IMPLEMENTATION CANDIDATE
Date: 2026-08-22

## Objective

Keep the Parallax mobile workspace stable and fully usable while the iOS virtual keyboard is open, without allowing Safari/WebKit viewport behavior to hide the persistent composer or zoom/crop the application.

## Problem

On iOS WebKit, opening the software keyboard can overlay rather than resize the layout viewport. Parallax currently anchors the composer to the layout viewport, so the keyboard can cover it. The mobile composer input also renders below 16 CSS pixels, which can trigger Safari focus zoom and make the workspace appear cropped or enlarged while typing.

## Requirements

1. Phone-sized web inputs use at least 16 CSS pixels so focusing an editable field does not trigger iOS automatic page zoom.
2. When WebKit reports a materially reduced visual viewport while an editable field is focused, the Parallax web root fits the visible viewport rather than remaining behind the keyboard.
3. Visual-viewport offset is compensated so iOS viewport panning does not move the application away from the visible region.
4. The persistent composer remains completely above the software keyboard and usable while typing.
5. The conversation and governed surfaces resize naturally within the remaining visible workspace; no product state or authority semantics change.
6. The workaround is web-only, activates only for a likely software-keyboard condition, and resets after focus/viewport recovery.
7. Android/desktop behavior remains unchanged when the layout viewport already resizes correctly.
8. Authentication, Work Specification approval, amendment recovery, Engineering Run binding, and bounded-autonomy authority are unchanged.

## Acceptance criteria

- A 390×844 browser acceptance test can simulate a WebKit-style 480px visual viewport with a non-zero offset while the composer is focused.
- Under that simulated keyboard condition, the application root fits the visible visual viewport and the composer bottom remains inside it.
- Mobile editable fields resolve to at least 16 CSS pixels.
- Restoring the full viewport removes the keyboard compensation and returns the root to normal geometry.
- Existing mobile Work Specification geometry acceptance continues to pass.
- Existing client typecheck, export, browser/Skia acceptance, API regression, protected promotion evaluation, DSPy release compilation, and bounded-autonomy gates continue to pass.

## Non-goals

- Disabling browser zoom globally or reducing accessibility.
- Replacing the native iOS keyboard.
- Changing Work Specification or conversation scope semantics.
- Changing application visual identity, product architecture, or autonomy authority.
